# Исследовательская цель: извлечение переносимой структуры связей

Зафиксировано: 29 сентября 2026 года.

**Актуализация 2 октября:** следующий этап — [Transformer-генератор и оценщик качества](PLAN_GENERATOR_EVALUATOR.md) по функциональному банку. Цель — улучшить качество относительно настроенного dense на каждой новой задаче. Ниже сохранена историческая постановка VAE/agreement от 29 сентября.

## Область работы

Рассматриваем извлечение общей бинарной маски связей из карт обученных сетей, VAE и поиск согласованных масок (agreement). Генератор `Gψ` и ветка генерации матрицы `U` в эту цель не входят.

Маска задаёт разрешённые связи; численные веса для каждой новой задачи обучаются с нуля. Бинарная маска сама по себе не задаёт разделение весов и не доказывает восстановление свёртки или эквивариантности.

## Формулировка задачи

Дано семейство задач, имеющих общую, заранее неизвестную структуру полезных связей нейронной сети. Каждая отдельная задача допускает множество структур с хорошим качеством, поэтому её решения недостаточно для определения переносимой закономерности.

Мы хотим по наборам решений нескольких обучающих задач выделить общую структуру, зафиксировать её и использовать при обучении новых задач того же семейства. Для новой задачи численные веса обучаются с нуля.

**Цель — извлечь переносимый структурный inductive bias, благодаря которому новая модель достигает заданного качества с меньшим количеством размеченных примеров.**

Концептуальный механизм из `paper`: для каждой исходной задачи оценить семейство структур, допускающих почти оптимальные решения, и найти структуру, совместимую с несколькими такими семействами. Agreement декодеров — проверяемый способ приблизить этот поиск, а не самостоятельный критерий достижения исследовательской цели.

## Проверяемые гипотезы

1. **Перенос структуры.** Общая маска, извлечённая только из исходных задач, помогает обучать новые задачи при ограниченном количестве данных.
2. **Польза разнообразия задач.** Совместимость с разнообразными исходными задачами позволяет выделить более переносимую структуру, чем использование одной задачи или нескольких VAE одной задачи.
3. **Дополнительная польза agreement.** Поиск согласованных масок в пространствах независимо обученных VAE даёт преимущество перед выровненной средней картой, отдельной VAE и прямым поиском маски при сопоставимых бюджетах.
4. **Структурный механизм.** Выигрыш связан с общей геометрией задач: он сохраняется при общей перестановке координат и ослабевает при нарушении согласованности геометрии между задачами.

Эти гипотезы проверяются отдельно. Выигрыш VAE над случайной маской не доказывает пользу agreement; совпадение выходов декодеров не доказывает восстановление общей закономерности.

## Что уже известно

- Есть положительные результаты переноса структурного prior на новые паттерны и длины, но преимущество правильного условия длины сверх общего prior не установлено: [отчёт 8 сентября](FINAL_REPORT_2026-09-08.md).
- На малой синтетике точное совпадение двух декодеров достигает 99,4%, но IoU с аналитической маской остаётся около 0,685: [отчёт 13 сентября](FINAL_REPORT_2026-09-13.md).
- На MNIST при итоговом ограничении связей agreement уступает выровненной средней карте в среднем на 0,26 п. п. при 2% связей и на 0,09 п. п. при 5%. Без ограничения порядок методов меняется; поиск и итоговая оценка используют разные ограничения: [отчёт 27 сентября](FINAL_REPORT_2026-09-27.md).
- В рассмотренных финальных отчётах нет кривых качества на новых задачах в зависимости от числа размеченных примеров, необходимых для проверки основного тезиса об эффективности по данным.
- В `paper` заявленная эффективность по данным и перенос на новые задачи ещё требуют экспериментального подтверждения. Формальные гарантии восстановления структуры не установлены.

## План экспериментов

### 1. Основной эксперимент: перенос фиксированной маски и эффективность по данным

Начать с `pattern` при фиксированных длинах входа и паттерна, чтобы проверить перенос между задачами без одновременного изменения геометрии.

**Протокол:**

1. Разделить паттерны на обучающие, валидационные и тестовые задачи.
2. Построить банки, обучить VAE и найти общую маску только на обучающих задачах. Валидационные задачи использовать для выбора настроек; тестовые задачи не использовать до итоговой оценки.
3. Зафиксировать маску. На каждой новой задаче обучать свежую MLP с нуля.
4. Менять число размеченных примеров новой задачи, например: 32, 64, 128, 256, 512 и 1024. Сетка предварительная; окончательно выбрать её до просмотра тестовых результатов.

**Сравнения:** agreement, выровненная средняя карта, отдельная VAE, прямая карта банка, случайная маска той же мощности, аналитическая локальная маска и плотная сеть.

**Главные метрики:** test loss и balanced accuracy как функции числа примеров; число примеров до заранее выбранного уровня качества. Порог качества должен быть выбран на валидационных задачах; недостигнутый порог явно отмечать.

**Критерий:** устойчивый выигрыш по данным на новых задачах. Превосходство только над случайной маской подтверждает полезность prior, но недостаточно для подтверждения дополнительной пользы agreement.

### 2. Вклад согласования, task loss и разнообразия исходных задач

На одинаковых банках и разбиениях сравнить:

| Вариант | Что проверяет |
|---|---|
| Средняя карта после выравнивания | Достаточно ли простого усреднения |
| VAE без поиска | Что уже содержится в prior |
| Поиск только по agreement | Достаточно ли согласованности декодеров |
| Поиск только по BCE исходных задач | Что даёт функциональный критерий |
| BCE + agreement | Есть ли дополнительная польза согласования |
| Прямой поиск общей маски по BCE | Помогает ли ограничение поиска пространствами VAE |

Повторить для 1, 2, 4 и 8 различных исходных задач. Для одной VAE межмодельный agreement не определён; использовать этот вариант как контроль без согласования. Отдельно сравнить несколько VAE одной задачи с VAE разных задач при сопоставимом общем объёме карт.

BCE при выборе структуры использует только исходные задачи; финальная оценка — на новых задачах. Сопоставлять вычислительные бюджеты поисковых методов, число кандидатов и объём данных. Для дешёвых методов отдельно показывать стоимость. Для каждого сравнения оценивать парную разность качества и её неопределённость.

### 3. Проверка извлечения общей геометрии

Сравнить три синтетических условия:

1. Паттерны с общей локальной геометрией.
2. Те же задачи после одной общей случайной перестановки входных координат.
3. Задачи с разными перестановками, нарушающими согласованность геометрии между задачами.

Во втором условии ожидается восстановление структуры в переставленных координатах. В третьем ожидается ослабление преимущества общей разреженной маски; отсутствие любого полезного общего ограничения заранее не предполагается.

Измерять качество на новых задачах, близость к известной структуре, покрытие нужных окон. Аналитическую маску использовать только для оценки, эталонного сравнения и явно выделенной oracle-диагностики. Случайным маскам применять те же процедуры сопоставления столбцов, что и изученным маскам: само выравнивание способно создавать видимую структуру.

### 4. Проверка пересечения семейств хороших решений

На маленькой задаче, где можно подробно исследовать множество масок, определить хорошую структуру: после обучения свежих весов её ошибка не хуже заранее определённого ориентира более чем на `ε`. Ориентир, допуск и бюджет обучения фиксируются до итоговой проверки.

Проверить:

- Какая доля масок VAE действительно хороша для её исходной задачи.
- Насколько полно VAE покрывает известное множество хороших структур, если его можно перечислить или надёжно оценить.
- Хороша ли найденная общая маска для каждой исходной задачи.
- Предсказывает ли совместимость с несколькими исходными задачами качество на новых задачах.

Этот опыт проверяет связь между agreement и заявленным в статье пересечением семейств пространств гипотез. Близость выходов декодеров сама по себе такой связи не устанавливает. Неудача oracle-поиска не доказывает отсутствия нужной структуры во всём образе декодера.

### 5. MNIST: одинаковые ограничения при поиске и оценке, строгий перенос

Сначала искать маску с тем же ограничением числа связей на пиксель и той же мощностью, с которыми она будет оцениваться. Варианты без ограничения и с ограничением проводить как отдельные согласованные протоколы.

Затем повторить перенос на нескольких заранее заданных разбиениях цифр и опорах выравнивания. Отложенные цифры не должны участвовать в поиске структуры даже как отрицательные примеры. После фиксации структуры разрешается обучать новые веса на обучающих примерах новых задач; итоговые тестовые изображения остаются независимыми.

Основные сравнения: средняя карта, отдельная VAE, прямая карта, agreement и случайная маска; плотная сеть — ориентир по качеству. Проверить кривые качества по объёму данных, а не только одну точку при большом обучающем наборе.

## Общие требования к протоколу

- Разделять задачи для обучения структуры, выбора настроек и итогового теста.
- Разделять входы для построения банков, выбора структуры и итоговой оценки. На синтетике проверять совпадения самих строк и, где требуется постановкой, орбит преобразований.
- Для новой задачи использовать support для обучения весов, отдельную validation/query-часть для разрешённого выбора состояний и test только для итоговой оценки. Не подбирать маску по меткам тестовой задачи в основном эксперименте переноса фиксированной структуры.
- Не использовать аналитическую структуру для обучения, выравнивания при поиске или выбора гиперпараметров основного метода. Oracle-диагностику маркировать отдельно.
- Сравнивать финальные бинарные маски с одинаковой мощностью и согласованными ограничениями. Качество мягкой маски не считать качеством разреженной бинарной архитектуры.
- Переобучать численные веса с нуля и использовать парные инициализации и данные там, где это возможно. Проверять достаточность горизонта обучения.
- Включать независимые обучения банков/VAE и разбиения задач. Старты `z`, маски и повторные обучения MLP внутри одного запуска не считать независимыми повторениями всего метода.
- Показывать средние, парные эффекты и интервалы неопределённости с указанной единицей независимости. Учитывать вложенность задач и повторов, а также повторное использование одних задач между разбиениями.
- До просмотра теста зафиксировать основные сравнения, метрики, сетки настроек, правила остановки и практически значимый размер эффекта.

Исторические результаты `motif-pair` с почти полным пересечением входов между выборками не использовать как доказательство обобщения на новые входы. Перед дальнейшими опытами этой ветки нужен независимый протокол разделения данных.

## Критерии достижения цели и порядок работы

**Общая исследовательская цель подтверждается**, если извлечённая и зафиксированная структура устойчиво улучшает эффективность обучения на независимых новых задачах, а контролируемые опыты поддерживают объяснение через общую структуру задач.

**Дополнительный вклад agreement подтверждается отдельно**, если он даёт устойчивое преимущество перед сильными простыми альтернативами, прежде всего выровненной средней картой, и сопоставимым поиском без agreement. При отсутствии такого преимущества результат следует формулировать как перенос полезного структурного prior без установленной дополнительной пользы agreement.

Точное восстановление единственной аналитической маски не является обязательным условием функционального успеха: задачу могут реализовывать разные структуры. Утверждения о точном или lossless-восстановлении требуют отдельной проверки и условий идентифицируемости.

**Первый этап:** эксперименты 1 и 2 на одной синтетической постановке. Затем эксперимент 3 для проверки механизма, эксперимент 4 для проверки предпосылки о семействах решений и эксперимент 5 для практической проверки на MNIST.
