# План: кооперативные генераторы масок и глобальный оценщик

Зафиксировано 2 октября 2026 года. Статус: implementation и CPU smoke полного
пайплайна проверены. Основной запуск — компактный `pattern-small`; пользователь
уже запустил большой `full` с 2000 шагами, но его результаты здесь не
интерпретированы.

Этот документ заменяет исходную версию с одним общим генератором. Исторический
одногенераторный протокол и его короткие проверки остаются описанными в
[прошлом плане](experiments_md/2026-10-02/01_transformer_surrogate_plan.md#историческая-версия-с-одним-генератором).

## Цель и разделение задач

Обучаем отдельный Transformer-генератор $G_i$ для каждого train-паттерна $i$.
Он описывает маски, поддерживаемые функциональными решениями именно своего
паттерна. Затем кооперативный поиск ищет одну бинарную маску, которую предлагают
несколько генераторов и которая даёт хорошее настоящее качество после нового
обучения весов на каждом train-паттерне. На старте это `0001` и `0011`; `0101`
остается запечатанным test-паттерном до заморозки выбора.

Для маски $M$ и задачи $\tau$ измеряем только качество терминальных весов,
обученных на support:

$$
Q_\tau(M)=\mathbb E_\xi\left[
L_{D_\tau^q}\left(
f_{\operatorname{Train}_T(D_\tau^s;M,\xi),M}
\right)
\right].
$$

Численные веса всегда свои для каждой новой сети. В `pattern-small` $T=500$
support-only шагов и две инициализации. Query не участвует в градиенте, остановке
или выборе весов. Улучшение не предполагается: функциональное пересечение
качественных семейств масок может оказаться пустым.

## Банки и модели

Каждый $G_i$ получает только свой индивидуальный функциональный банк. Для
каждого решения банк хранит один и тот же probe, токены профилей вкладов,
signed/absolute/RMS sensitivity, исходную маску и полное состояние. Эти же
представление, шкалы и probe применяются к картам обратной связи: модель,
обученная с предложенной sparse-маской, возвращается в банк своего паттерна
полной функциональной картой и state.

Чтобы генератор не видел только dense-представления и не получал sparse
functional-map mismatch, начальный банк каждого паттерна строится на пяти
плотностях $K\in\{9,32,44,62,88\}$, включая dense. В `pattern-small` по одному
teacher-решению каждой плотности, всего 5 на паттерн; teacher обучается 200
support-only шагов с одной инициализацией, probe имеет 32 точки. Реальная
evaluator-метка по-прежнему получается отдельным 500-шаговым fit с двумя
инициализациями.
Якоря по плотности сохраняются при обновлении банка. Генератор получает
budget-conditioning, но предлагает только финальный agreement с ровно $K=32$
из матрицы $11\times8$. В его обучении чередуются представления всего
mixed-density банка и одного уровня плотности, чтобы защититься от sparse input
mismatch без отдельного auxiliary-acquisition этапа.

Модель намеренно мала: Transformer ширины 16 с двумя heads, одним слоем и
noise-размерностью 4. Глобальный evaluator — ансамбль из двух членов. Это
достаточно для проверки механики agreement на `pattern` и не претендует на
универсальный архитектурный выбор. Fits одинакового размера выполняются
батчами; семантика отдельной маски и инициализации от этого не меняется.

Policy-обновление каждого $G_i$ минимизирует predicted delta только его
собственного паттерна $i$, а не общий worst-task objective. Общая структура
появляется отдельным agreement-шагом ниже.

Оценщик один, глобальный и context-conditioned: ансамбль
$\widehat Q_\phi(M,c_\tau)$ принимает маску и support-context конкретного
паттерна. Он обучается только по настоящим train-меткам всех train-паттернов:

$$
L_{\mathrm{eval}}=\mathbb E_{(M,c_\tau,q)}
\left(\widehat Q_\phi(M,c_\tau)-q\right)^2.
$$

Среднее ансамбля используется для acquisition, разброс — только диагностика
неопределенности. Прогноз никогда не становится pseudo-label. Метки holdout
топологий сохраняются в replay с диагностической ролью, но не поступают в
optimizer/evaluator train, feedback-банки или distillation; данные выбора имеют
то же ограничение.

## Кооперативный поиск

Латентный поиск не является отдельной стадией. В каждом раунде каждый $G_i$
предлагает набор точных top-$K$ масок, после чего предложения образуют общий
пул. Его дополняют случайная exploration и edge-swap мутации qualified elites.
Глобальный оценщик делает кросс-оценку: **каждая** маска пула оценивается на
context обоих train-паттернов. Кандидаты ранжируются по худшему предсказанному
изменению относительно dense:

$$
\widehat C(M)=\max_{\tau\in\{0001,0011\}}
\left[\widehat Q_\phi(M,c_\tau)-Q_\tau(M_{\mathrm{dense}})\right].
$$

В acquisition смешиваются перспективные кандидаты, неопределенные кандидаты и
случайные кандидаты из полного пула. Для terminal fits используются только
явно материализованные generator proposals, random exploration или elite
edge-swap mutations; суррогат не создаёт меток. Каждая выбранная маска измеряется
на обоих train-паттернах; отобранные feedback-карты возвращаются в банки
соответствующих генераторов по правилу ниже. Лучшие общие маски можно distill-ить
в оба генератора только после их отдельной проверки настоящим качеством; это не
заменяет реальные измерения.

В feedback возвращаются не все acquisition-результаты. Для каждой train-топологии
сохраняется одна карта **каждой** плотности, чтобы не потерять anchors, и один
дополнительный лучший совместный кандидат с целевым $K=32$. Held-out
карты исключены. Общая элита допускается к
distillation только при настоящих метках $Q_\tau(M)\le Q_\tau(M_{\mathrm{dense}})$
для обоих train-паттернов с margin $0$. После локального policy-шага каждый
генератор делает второй optimizer step: column-Hungarian выравнивание и BCE на
этой элите с весом $0.1$. Это не является shared worst-task policy gradient.

В `pattern-small` оценщик обучается 10 эпох на начальном наборе истинных
измерений и обновляется в каждом из двух generator-раундов; каждый раунд содержит
4 updates. Измеряются две кросс-проверяемые маски за раунд. Во время обновления
генераторов оценщик фиксирован. Более затратный `full` preset сохраняет исходные
50 эпох и адаптивную cadence.

## Разделение, выбор и test

По умолчанию train — `0001,0011`, test — `0101`. CLI проверяет, что все
паттерны различны и не принадлежат одной орбите reversal/complement; выбор можно
настроить только на дизъюнктных орбитах. Третьей validation-задачи нет.
Checkpoint, solver и общая маска выбираются на независимом validation-pool
наблюдений **тех же двух train-паттернов**. До открытия `0101` фиксируются маска,
checkpoint и solver; test-паттерн не используется для feedback, distillation,
настройки или выбора.

В `pattern-small` `test_support=64` и `test_query=64` — отдельные
зарезервированные pools.
Test query выбирается равномерно и не зависит от class-balanced support-count,
поэтому его class prior не наследует bias support-набора.
До teacher fits opaque preflight читает только class counts будущего test-support,
чтобы отклонить невозможный balanced size; test-query и финальные `TaskData`
остаются закрытыми до frozen checkpoint, без сохранения их labels или features.

Финальная проверка обучает новые веса с замороженной маской на `0101` и сравнивает
её с настроенным dense, random и двумя функциональными baselines — по одному от
каждого train-паттерна. Новый cooperative CLI не запускает прямой REINFORCE
контроль; он остаётся возможностью legacy shared-generator runner. Отчёт содержит
по-паттерновые реальные ошибки, разрыв evaluator, состав общего пула, степень
agreement, raw/canonical overlap предложений, полные состояния и provenance; он
не заявляет гарантии улучшения accuracy.

## Запуск

Cooperative runner реализован. Команда не запускает вычисления автоматически из
документации:

```bash
CUDA_VISIBLE_DEVICES=GPU-6784dc4e-6ec9-2266-5d23-85bf1b1c2af3 \
python -u -m generator_evaluator.cooperative_run \
  --train-patterns 0001 0011 --test-pattern 0101 \
  --preset pattern-small --seed 4100 --device cuda:0 --progress \
  --out outputs/generator_evaluator/20261002_pattern_small_seed4100
```
