# MLP: связанные логические части

## Две схемы сбора, актуальный пилот

По уточнению пользователя реализован внешний поиск структур. Четыре
сочетания позволяют отдельно проверить выбор кандидатов и внутреннее обучение:

| Предложения | Обучение внутри кандидата |
| :-- | :-- |
| Независимые случайные структуры | Индексы фиксированного codebook |
| Эволюция структур | Индексы фиксированного codebook |
| Независимые случайные структуры | Свободные численные веса |
| Эволюция структур | Свободные численные веса |

Кандидат содержит маски связей и по два codebook из девяти чисел на слой:
для весов и смещений. Индексатор назначает каждой позиции ближайшее число
codebook по обучаемому вещественному параметру. В прямом проходе значение
дискретное; в обратном производная квантования заменяется единицей
(straight-through). SGD с моментом обучает вспомогательные параметры,
а сами числа codebook фиксированы. Это не точный градиент дискретного индекса.
В варианте со свободными весами codebook не используется.

Эволюция наследует маски и масштабы codebook, скрещивает связи на уровне
нейронов, меняет связи и сохраняет случайных иммигрантов. При каждой оценке
численные или вспомогательные параметры обучаются с нового старта.
Никаких истинных групп, масок или промежуточных ответов генератору кандидатов
не передаётся. Архитектура одинакова: 64–64–16–4–1, входы центрированы.

В `protocol_search.json` заморожены 16 популяций по 16 кандидатов, 512 шагов
на кандидата, batch 128. Это 256 кандидатов на каждую из четырёх полных
исходных задач для каждого метода. Используются задачи предыдущей
калибровки: это разработка сбора банка, не независимая проверка переноса.
Все четыре поиска завершаются до оценки на независимых 16 384 примерах.

В `protocol_refit.json` отдельно зафиксировано продление внутреннего
обучения выбранных структур: шесть стартов по 16 384 шага и новая
итоговая выборка. Этот диагностический этап добавлен после просмотра
хода исходного поиска; его нельзя описывать как заранее зафиксированный
основной протокол.

```bash
CUDA_VISIBLE_DEVICES=5 /home/udeneev-av/myvenv/bin/python \
  experiments/mlp_logic_v1/search.py --output results/search_v1
CUDA_VISIBLE_DEVICES=5 /home/udeneev-av/myvenv/bin/python \
  experiments/mlp_logic_v1/refit.py
/home/udeneev-av/myvenv/bin/python experiments/mlp_logic_v1/report_search.py
```

Нужны NumPy, PyTorch и Matplotlib из `/home/udeneev-av/myvenv`.
Каталог результата должен отсутствовать; существующие запуски не перезаписываются.
Для воспроизведения после изменений использовать замороженные копии
исходников в каталогах результатов (`run_snapshot.py` импортируется как
`run.py`, `search_snapshot.py` — как `search.py`).

Графики loss, recall обоих классов, сравнения и таблицы публикуются в
`mds/MLP_STRUCTURE_SEARCH_PILOT_2026-10-28.md`. Сохраняются все предложенные
структуры и качества, модели победителей и дискретные индексы. Лучшие
неуспешные кандидаты не обозначаются как успешные точные решения.

## Уточнение: банк частичных решений

Пользователь уточнил, что точные исходные решения могут быть не нужны.
В `protocol_weak_bank.json` и `weak_bank.py` добавлено извлечение из всех
96 моделей длинного этапа. Вес модели — улучшение проверочной BCE
относительно постоянного прогноза частоты класса, с вычетом 0.005.
Итоговая оценочная выборка при отборе не используется.

По совместному участию входов в обученных нейронах строится матрица близости,
из неё восстанавливается иерархия из восьми групп по восемь входов.
Контроль строит близость по тем же выбранным маскам без обученных значений.
Истинные группы используются только после замораживания prior: для
диагностики, генерации ответов новых задач и отдельного oracle-контроля.

Затем две новые задачи выбирают шаг обучения, а восемь отдельных задач
оценивают перенос. Сравнения: группы по частичным решениям, по одним маскам,
перемешанные группы, правильные группы, плотные Adam и SGD. Все численные
веса обучаются заново, четыре старта по 8192 шага. Сохраняются loss и recall.

Результат: положительный вес у 21 модели, все относятся к одной из четырёх
исходных задач. Доля правильно объединённых пар входов — 35.7% против
11.1% в случайной группировке и 12.9% по одним маскам. Ни одной полной
группы не восстановлено. На новых задачах BCE 0.6381 против 0.6383 у плотного
Adam; убедительного выигрыша переноса в этой серии нет.

```bash

  experiments/mlp_logic_v1/weak_bank.py
MPLCONFIGDIR=/tmp/mlp-logic-matplotlib /home/udeneev-av/myvenv/bin/python \
  experiments/mlp_logic_v1/report_search.py
```

## Архивная калибровка плотных методов

Статус на 28 октября: `results/calibration_v1` завершён, 96 обучений,
0/4 задач прошли критерий качества. Пользователь остановил эту схему сбора:
успех плотного SGD не является необходимым условием получения банка.
Следующее направление — внешний поиск структур, например эволюционный,
с обучением численных весов внутри кандидатов. Такой поиск ещё не запускался.
Контроль с правильной маской, банк и целевые задачи также не запускались.
Описание ниже сохраняет исходный план калибровки, а не действующее условие
продолжения исследования.

Пилот проверяет предпосылки переноса структуры между полными задачами.
Начальный этап — калибровка обучаемости, а не сравнение на целевых задачах.

Вход — 64 независимых равновероятных бита. Скрытая случайная перестановка
разбивает координаты на восемь групп по восемь. Для каждой задачи:

- в каждой группе два блока независимо выбирают четыре разных входа;
- каждый из 16 блоков вычисляет XOR четырёх битов или пороговую функцию
  «не менее двух/трёх единиц»;
- четыре блока второго уровня получают по четыре результата первого,
  объединяя две соседние скрытые группы; выполняют те же операции;
- выходной блок объединяет все четыре результата второго уровня.

Вероятность XOR — 1/2 на каждом уровне. Схемы, не содержащие обеих операций,
и задачи с долей единиц вне [0.2, 0.8] на отдельной выборке генерации
отбрасываются. Перестановка и иерархия общие; конкретные связи и операции
меняются. Генератор и все отклонённые попытки сохраняются. Граф учителя
используется для ответов и диагностики, а не для обучения или извлечения
структуры.

Каждый логический блок точно представим четырьмя ReLU от суммы его входов.
Поэтому учитель — ReLU-MLP 64–64–16–4–1. Ученики — обычные плотные
ReLU-MLP 64–128–64–16–1, с обучаемыми смещениями. Они получают только
входы и конечные бинарные ответы. Оптимизируется binary cross-entropy.

В `protocol.json` до запуска фиксируются диапазоны настроек и условия
продолжения. На четырёх полных исходных задачах сравниваются девять
настроек Adam и три SGD с моментом, по два старта. На старте генерируются
новые обучающие данные; валидация выбирает лучший чекпойнт каждого старта.
Отдельные 16 384 примера оценивают выбранные модели.

Успех: accuracy ≥ 0.97 и recall каждого класса ≥ 0.95. Если не решены
хотя бы три из четырёх задач, сбор банка и перенос не запускаются: в этом
режиме не выполнена предпосылка «извлечь структуру из многих решений».
Это диагностический неуспех постановки, а не доказательство пользы метода.

План после прохождения калибровки: восемь новых полных исходных задач,
извлечение общей иерархии из обученных весов и восемь новых целевых задач.
Контроли: плотные SGD/Adam, перенос весов, готовая исходная маска,
случайная иерархия, локальный поиск масок и правильная иерархия.
Эти этапы нельзя считать выполненными, если сохранён только результат
калибровки. Бюджет банка учитывается отдельно; перенос весов получает тот
же банк.

На первом уровне только выборы четырёх входов внутри восьмёрок уже дают
70^16 схем. Это число записей генератора, а не число доказанно различных
функций: перестановки блоков, общие операции и алгебраические упрощения
создают эквивалентности. Трудность полного перебора не означает трудности
для любого специализированного алгоритма.

recall обоих классов и независимая итоговая оценка.
