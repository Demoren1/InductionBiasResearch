# Индексатор, свежий кодбук и плохие локальные минимумы

[Проверка теории](../../mds/theory/BASIN_TRANSFER_THEORY_AUDIT_2026-11-02.md).
[Результаты трёх режимов](../../mds/BASIN_STRUCTURE_TRANSFER_RESULTS_2026-11-02.md).
Протокол `protocol.json` зафиксирован до создания целевых функций.

Цель — проверить оптимизационный механизм прежнего sine-опыта для
полностью обучаемых кодбуков. 24 входа разбиты на 3 скрытые группы
общих весов; отключённых связей нет. Четыре исходные структуры,
по 6 низкочастотных функций на структуру, по 4 плотных старта.
Из весов извлекаются индексаторы, на них обучаются 3 независимых MADE.

На новых функциях той же структуры меняется направление внутри её
подпространства, низкая/высокая частоты и слабая амплитуда. Цель —
сумма слабого низкого и сильного высокого sine; один нейрон ученика
создаёт конкуренцию двух решений. Генератор заморожен, каждый кодбук
и выходная амплитуда обучаются заново. Неизвестная пятая структура
включена как отдельный отрицательный контроль.

Численные методы обучаются на свежих Gaussian-minibatch. Query выбирает
настройки и checkpoints; population MSE используется только для отчёта
и отдельной геометрической диагностики. Успех — MSE меньше 0,1.
32 попытки по 2048 шагов; длинный dense — 8 по 8192, тот же бюджет
обновлений и примеров. Отдельная калибровка шага, оптимизатора и нормы
старта у структурного метода и плотных SGD, SGDM, Adam. Source-transfer
проверяется с Adam; это отдельный конкурент с численной инициализацией.

Нормированные координаты групп устраняют множитель их размера в GD.
Радиус начальных весов выбирается из общей сетки; заданный радиус точно
одинаков в 3- и 24-мерном пространстве. Контроль `release_ar_0` получает
ту же AR-структуру и свежие числа, но с первого шага обучает все веса.
Никакой кодбук в основном методе не переносится из источника.

Из корня репозитория, на свободной GPU:

```bash
CUDA_VISIBLE_DEVICES=5 python3 -m experiments.basin_structure_transfer_v1.run prepare
CUDA_VISIBLE_DEVICES=5 python3 -m experiments.basin_structure_transfer_v1.run calibrate
CUDA_VISIBLE_DEVICES=5 python3 -m experiments.basin_structure_transfer_v1.run evaluate
CUDA_VISIBLE_DEVICES=5 python3 -m experiments.basin_structure_transfer_v1.audit
```

Объявленное после первого результата продолжение с новыми функциями:

```bash
CUDA_VISIBLE_DEVICES=5 python3 -m experiments.basin_structure_transfer_v1.frequency_sweep --frequency 6
CUDA_VISIBLE_DEVICES=7 python3 -m experiments.basin_structure_transfer_v1.frequency_sweep --frequency 8
CUDA_VISIBLE_DEVICES=5 python3 -m experiments.basin_structure_transfer_v1.audit --frequency 6
CUDA_VISIBLE_DEVICES=7 python3 -m experiments.basin_structure_transfer_v1.audit --frequency 8
python3 -m experiments.basin_structure_transfer_v1.report
```

При частоте 4 плотные SGDM/Adam решают все 32 знакомые функции.
При частотах 6 и 8 — 0/32, AR — 25–30/32 и 18–20/32, retrieval —
32/32 и 23/32. Публикуются все три режима. Полный разбор различает
геометрию минимумов, успех свежего кодбука и покрытие генератора.

Фазы не перезаписывают готовые каталоги. `frozen_before_target.json`
фиксирует протокол, генераторы, банки, калибровку и основной код до
создания итоговых задач. Истинные I используются только oracle и
диагностикой. Банки численных исходных весов отделены от входов MADE.

Точные исходники запусков до последующего форматирования сохранены
в `results/code_snapshot/manifest.json`; хеши снимка соответствуют
зафиксированным входам запусков. Форматирование не требовало повторного
обучения. Норма старта контролируется одинаковой сеткой кандидатов;
выбранные конкретные радиусы разных методов могут различаться.

Исследовательские обучения и диагностики не являются модульными тестами;
новые тесты в репозиторий не добавляются.

Разбор сохранённых неудач без нового обучения:

```bash
python3 -m experiments.basin_structure_transfer_v1.diagnose_failures
```

Он вычисляет массу каждой структуры, проверяет первый символ,
разделяет ошибки предложения, нового кодбука и query-отбора.
Результаты и возможное перераспределение бюджета описаны в
[диагностической записке](../../mds/BASIN_GENERATOR_FAILURE_DIAGNOSIS_2026-11-02.md).
