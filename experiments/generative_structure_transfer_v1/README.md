# Генерация изученных структур и обучение новых кодбуков

[Результаты завершённого пилота](../../mds/GENERATIVE_STRUCTURE_TRANSFER_PILOT_2026-11-02.md),
[теоретическая постановка](../../mds/theory/GENERATIVE_STRUCTURE_TRANSFER_THEORY_2026-11-02.md).

Пилот от 2 ноября 2026. Генеративная модель обучается **только выдавать
индексаторы**. На новой задаче её параметры заморожены. Для каждой попытки
выбирается индексатор, после чего все 32 численных значения кодбука
инициализируются независимо от исходных весов и обучаются с нуля.
Индексатор во время этой попытки неизменен. Ни генерации, ни переноса,
ни фиксации численных кодбуков в основном методе нет.

## Постановка

У всех методов одна MLP: 32 входа, 16 tanh-нейронов, фиксированные нулевые
смещения и выходные коэффициенты 1/4. Существуют четыре разные скрытые
схемы распределения 512 весовых позиций по 32 группам. В каждой исходной
семье шесть разных функций используют общую схему и разные численные
параметры. Исходные плотные сети учатся только по конечным ответам функций.
Из их весов извлекаются индексаторы; истина используется для диагностики
и отдельно обозначенного oracle-контроля.

В генеративное обучение поступают только извлечённые индексаторы. Веса,
ответы, численные параметры учителей и идентификатор нужной целевой семьи
не являются входом генератора. Четыре семьи нужны для проверки того,
сохраняет ли совместная модель целые изученные схемы при сэмплировании.
Новых сочетаний структур для успеха этого опыта не требуется.

При подготовке банка известна принадлежность исходных задач к семье.
Нейроны и номера кодов согласуются внутри семьи относительно решения
одной из четырёх обучающих функций. Между разными семьями сопоставление
нейронов не навязывается. Генератор обучается на общем наборе без меток
семей; целевая принадлежность неизвестна решателю.

Модель MADE выбирается по NLL структур двух отложенных исходных функций
каждой семьи. Температура и шаги численной оптимизации выбираются затем
на восьми отдельных калибровочных функциях. После фиксации настроек
создаются 16 новых функций известных семей и четыре функции с пятой,
незнакомой схемой. Численные параметры новых функций независимы от
исходных; это свойство генератора данных, а не действие нашего решателя.

## Проверяемая гипотеза

Изученная совместная модель должна с достаточной вероятностью предлагать
индексатор, в котором свежий кодбук обучается до малой ошибки. Поэтому
отдельно измеряются частота подходящих структур, успех численного обучения
при правильной структуре и ошибка окончательно выбранного решения.

Контроли: истинный индексатор; перенос целого исходного индексатора;
независимые частоты назначений; случайное назначение с теми же размерами
групп; плотные SGDM и Adam; дообучение исходных численных весов как отдельный
конкурирующий метод. Для плотных методов дополнительно предусмотрен
четырёхкратный горизонт. Проверяются 128 и 2048 примеров для градиентов,
в обоих случаях ещё 256 для выбора старта/состояния и независимые 8192
для оценки. Малая обучающая выборка вложена в большую; функции, query
и test совпадают между режимами. Полный доступный обучению бюджет меток
составляет 384 или 2304. Эти режимы не считаются независимыми задачами.

Принадлежность к семье скрыта от выбора кандидатов. Во всех основных
методах 16 попыток по 4096 шагов; настройки выбираются до целевого этапа.
Равенство числа попыток и шагов не означает равенства времени или FLOPs:
сохраняется фактическое время генерации, обучения и исходной подготовки.

Дополнительный вариант выбирает по query между структурным решением и
полноценным плотным baseline. Он расходует бюджет обоих методов. Выбор по
конечной query не является безусловной гарантией отсутствия ухудшения
test-NMSE; это проверяется отдельно, особенно на незнакомой структуре.

Это небольшой пилот одной библиотеки из четырёх структур. Повторные старты
и функции внутри семьи не считаются независимыми повторениями всего
метода. Превосходство над переносом целой структуры не предполагается:
его отсутствие совместимо с успешным переносом структуры на новые функции.

## Запуск

Все обучаемые модели используют CUDA. Сначала для каждой семьи
с номером от 0 до 3:

```bash
CUDA_VISIBLE_DEVICES=5 python -m experiments.generative_structure_transfer_v1.source --family 0
```

После готовности четырёх исходных банков:

```bash
CUDA_VISIBLE_DEVICES=5 python -m experiments.generative_structure_transfer_v1.run --stage prior
CUDA_VISIBLE_DEVICES=5 python -m experiments.generative_structure_transfer_v1.run --stage calibrate --support 128
CUDA_VISIBLE_DEVICES=5 python -m experiments.generative_structure_transfer_v1.run --stage evaluate --support 128
```

Повторить только калибровку и оценку с `--support 2048`. Генератор общий
для обоих режимов. На исходной калибровке подбираются два масштаба
инициализации, пять шагов численного обучения, три температуры;
длинные плотные варианты выбирают свои настройки. Query выбирает
состояние/попытку, итоговый test в подборе не участвует.

Не перезаписывать существующий результат: для нового опыта задать
отдельный `output` в протоколе. `report.py` читает завершённые артефакты
и сохраняет таблицы/рисунки; он не обучает модели.
