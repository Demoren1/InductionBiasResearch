# aSRR в протоколах текущей статьи

Добавление aSRR к исходному сравнению на двух синтетических геометриях,
MNIST, Fashion-MNIST и HAR. [Протокол](PROTOCOL.md) зафиксирован до
обучения новых банков. Старые результаты не перезаписываются.

Используются те же наблюдения, сетка бюджетов, численные оптимизаторы,
development и тестовые эпизоды, что у `paper_recovery_extension_v1`.
Это добавление метода к уже исследованным средам. Выборы aSRR фиксируются
до его query-оценки; source-параметры не переносятся в новые задачи.

`prepare.py` создаёт отдельный runtime и восстанавливает удалённые входы
HAR. `extract.py` использует существующие Ward-генераторы aSRR.
`worker.py` вызывает общие численные обработчики статьи; `queue.py`
распределяет независимые задачи по GPU. `synthetic.py` использует
исходный численный решатель и воспроизводит исходные target-функции.
`evaluate.py` фиксирует выборы/предсказания и выполняет отдельную оценку.

Runtime: `artifacts/local/paper_asrr_2026-11-17`.
Компактные результаты: `artifacts/paper_asrr_2026-11-17`.
Оценку и подготовку не следует повторять поверх завершённых каталогов.
Очередь пропускает только задачи с успешной квитанцией; частичные ошибки
требуют осмотра перед возобновлением.

После завершения таблицы и график воспроизводятся без обучения:

```bash
MPLCONFIGDIR=/tmp/paper-asrr-mpl python -m experiments.paper_asrr_v1.report
make -C paper
```

Старый генератор `paper_recovery_extension_v1.report` воспроизводит
сравнение без aSRR; для текущей расширенной версии нужен указанный выше
генератор. Программные тесты не создавались и не запускались.
