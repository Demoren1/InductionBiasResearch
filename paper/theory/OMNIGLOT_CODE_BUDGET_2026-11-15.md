# Omniglot: проверка количества кодов

15 ноября 2026. Дополнение после вопроса пользователя о достаточности
числа кодов. В [первом опыте](/home/udeneev-av/InductionBiasResearch/paper/theory/OMNIGLOT_DENSE_PRIOR_2026-11-15.md)
общий индексатор выбирался из 16/64/256 кодов, и минимум development CE
оказался на верхней границе. Эта сетка не позволяла заключать, что кодов
достаточно.

**Результат расширения:** development выбрала 4096 кодов. На 128 новых
эпизодах общий фиксированный индексатор получил 79,91%, dense — 80,44%.
Исходный общий индексатор с 256 кодами на тех же эпизодах получил 69,28%.
Увеличение бюджета и уточнение групп устранили большую часть отставания.

Позднее сохранённые FC-базисы MSR отдельно оценены на тех же эпизодах:
при 64 коэффициентах MSR получил 67,72%, G34 при 64 кодах — 65,41%.
Широкого подбора MSR пока нет; подробности и ограничения — в
[дополнении о MSR](/home/udeneev-av/InductionBiasResearch/paper/theory/OMNIGLOT_RETAINED_MSR_2026-11-15.md).

## Как расширена структура

Исходный полный G34-индексатор с 256 кодами последовательно уточняется
до 512/1024/2048/4096/8192 кодов. Новые группы получаются делением старых.
Для деления используются траектории весов шестнадцати прежних source
dense-задач после выравнивания и положительной калибровки. Разброс траекторий
определяет группу и координату для следующего медианного разделения.
Полная связность и знаки наследуются. Во всех сохранённых структурах
реально представлены все заявленные коды.

Каждая уточнённая структура допускает все функции предыдущей: новым
подгруппам можно присвоить численное значение их прежней общей группы.
Это содержательная проверка жёсткости найденного sharing. Она не является
полным новым поиском G34 для каждого бюджета и не доказывает, что другой
индексатор с 256 кодами обязательно хуже. Рост бюджета также меняет
условия численной оптимизации; их вклад отдельно не изолирован.

Контроль извлечения из одной задачи использует signed Lloyd с
64/256/512/1024/2048/4096/8192 кодами. Скалярный nearest-neighbor шаг
вычисляется через сортировку; сохраняются двадцать Lloyd-обновлений и
восстановление непустых групп. Полные 12 544 независимых веса представлены
dense-контролем: это точная функциональная свобода случая «код на вес».

Для крупных бюджетов численное обучение вычисляет веса прямым lookup
вместо хранения большого тензора признаков. Adam, шесть начальных
численных состояний, сетка скоростей, 200 шагов и выбор по валидации
сохранены. Контроль при 256 кодах дал development CE 0,90865 против
прежних 0,90868; смена способа вычисления не объясняет крупный эффект.

## Выбор на development

Те же 48 development-задач, выбор по среднему CE на evaluation-панели.
Полный dense включён в выбор как вариант полной свободы.

| Кодов | Общий индексатор: CE | Single-task Lloyd: CE |
|---:|---:|---:|
| 64 | — | 0,8344 |
| 256 | 0,9087 | 0,8605 |
| 512 | 0,7779 | 0,8128 |
| 1024 | 0,7088 | 0,7589 |
| 2048 | 0,7589 | 0,6824 |
| 4096 | **0,6570** | **0,6601** |
| 8192 | 0,6686 | 0,7155 |
| 12 544, dense | 0,6669 | 0,6669 |

Обе процедуры выбрали 4096, включая сравнение с полной свободой.
Это внутренняя точка расширенной сетки. Наблюдаемая немонотонность CE
совместима с вложенностью классов функций: измеряется результат конечного
обучения и валидационного выбора, а не оптимальный population risk.

## Новые эпизоды после фиксации бюджета

После фиксации выбора сгенерированы другие 128 эпизодов из тех же
423 test-символов, seed 3511158405 вместо 3511158404. Постановка прежняя:
784–16–5 ReLU, 5 разных символов, по 10 train + 5 numerical-validation +
5 evaluation рисунков на символ, без query augmentation. Все численные
параметры обучены заново. Предсказания пяти методов зафиксированы до
первого чтения новых evaluation-ответов; дополнительный фиксированный
256-code контроль имеет отдельную квитанцию фиксации до scoring.

| Метод | Кодов / весов | Accuracy, % и 95% CI | CE |
|---|---:|---:|---:|
| Dense | 12 544 | 80,44 ± 1,61 | 0,6319 |
| Общий G34, исходные группы | 256 | 69,28 ± 1,98 | 0,9175 |
| G34 → dense, один шаг без штрафа | 256 | 74,12 ± 2,04 | 0,8343 |
| Общий G34, уточнённые группы | 4096 | 79,91 ± 1,57 | 0,6293 |
| Извлечение из одной задачи, Lloyd | 4096 | 79,06 ± 1,62 | 0,6783 |

Парные разности accuracy для уточнённого общего индексатора:

- Против фиксированного 256-code варианта: +10,63 п.п., CI [8,83; 12,42].
- Против адаптированного 256-code варианта: +5,78 п.п., CI [4,18; 7,38].
- Против dense: −0,53 п.п., CI [−1,50; 0,44].
- Против single-task Lloyd при том же числе кодов: +0,84 п.п., CI [−0,09; 1,78].

Уточнённый общий индексатор фиксирован на всех новых задачах. Его группы
не используют target dense-решение; оно нужно контрольным методам с
извлечением и адаптацией под задачу. По сравнению с dense численных
весов первого слоя примерно втрое меньше. Эти числа не являются
измерением end-to-end ускорения или общей стоимости хранения.

## Выводы и границы

Первоначальный диапазон кодов был слишком узким. Для полученной структуры
более свободный sharing существенно улучшает качество; с 4096 кодами
различие с dense по accuracy не установлено в этом опыте. Это не доказанная
эквивалентность или заранее заданный non-inferiority результат.

Преимущество общего индексатора над отдельным извлечением при том же
бюджете также пока не установлено. Неизвестный истинный sharing Omniglot
этот опыт не восстанавливает и минимально необходимое число кодов
теоретически не определяет. Интервалы условны на одном source-ансамбле.

Отрицательный результат штрафа из первого опыта относится к 256 кодам.
Для новых бюджетов он здесь не подбирался: результаты выше проверяют
ёмкость и общий фиксированный индексатор. MSR в этом дополнении не
переобучался; прежние FC-контроли не следует смешивать с новой таблицей
как с полноценным сравнением методов статьи MSR.

Основной follow-up занял 523 с на CPU, дополнительный фиксированный
контроль шёл отдельно. Это время всей сетки, не скорость одного метода.
Рукопись и остановленная CNN image suite не изменялись. Software tests
не создавались и не запускались.
