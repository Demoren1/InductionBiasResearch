\section{Preliminary}
\label{sec:preliminary}

A trained network contains information about both the numerical values of
its parameters and the relations between them. For example, a predictor
may use only a subset of the available connections and share a coefficient
across several of them. These relations may remain useful on another task
even when the required coefficients change. Learning such constraints
from related tasks could therefore help a new predictor generalize from
limited data. We evaluate their usefulness through the quality of the
solutions obtained after learning new numerical parameters.

\subsection{Multi-task learning}
\label{sec:tasks}

Multi-task learning uses information shared by related prediction tasks
to improve learning. In our setting, each task $\tau$ is a supervised
learning problem with its own distribution $P_\tau$ over input--target
pairs $(x,y)$. Tasks share input and target spaces $\mathcal{X}$ and
$\mathcal{Y}$, but may require different predictors. We model their
relationship through a task family $\mathcal{T}$ and a distribution
$p(\tau)$ describing which tasks occur \cite{baxter2000model}.

We use source tasks $\mathcal{T}_{\mathrm{tr}}$ to learn shared structural
information and a disjoint collection of target tasks
$\mathcal{T}_{\mathrm{te}}$ to assess its transfer. Both collections are
drawn from the same task environment. For each task, a support sample
$S_\tau^{\mathrm{s}}$ provides examples for fitting the numerical
parameters. An independent query sample $S_\tau^{\mathrm{q}}$ provides
examples for comparing the resulting predictors
\cite{finn2017model,zhou2021meta}. Both samples contain observations
drawn independently from $P_\tau$. For a predictor $f$ and a sample $S$,
we measure performance by the average prediction loss
\begin{equation}
    \mathcal{L}_S(f)
    :=\frac{1}{|S|}\sum_{(x,y)\in S}\ell(f(x),y).
    \label{eq:task-loss}
\end{equation}
Here, $\ell$ is the loss for a single example, such as cross-entropy
for classification or squared error for regression.

\subsection{Network structure}
\label{sec:network-structure}

We fix a common network architecture and collect the weights to be
structured into a vector $w\in\mathbb{R}^{P}$, where $P$ is the number
of selected weight positions. An integer array
$I\in\{0,\ldots,K\}^{P}$, called an \emph{indexator}, assigns each
position to an entry of a \emph{codebook}
$C_\tau=(C_{\tau,0},\ldots,C_{\tau,K})$. The codebook contains $K$
trainable values and a fixed zero entry. The effective weights are
\begin{equation}
    w_p=C_{\tau,I_p},\qquad p=1,\ldots,P,\qquad C_{\tau,0}=0.
    \label{eq:indexator-weights}
\end{equation}
Connections with the same positive index must share a numerical value;
index zero disables a connection. Thus, $I$ specifies both connectivity
and weight sharing, while $C_\tau$ supplies the values for a particular
task. A connectivity mask is a special case in which each active
connection has its own trainable codebook entry.

For example,
$$
    I=(1,2,1,0),\qquad C_\tau=(0,0.7,-1.2)
    \quad\Longrightarrow\quad w=(0.7,-1.2,0.7,0).
$$
The first and third weights are tied, and the fourth is fixed at zero.
On another task, the same indexator can use different codebook values
while preserving these relations. We write $f_{I,C_\tau,\theta_\tau}$
for the resulting predictor, where $\theta_\tau$ contains any remaining
trainable parameters, such as biases. Both $C_\tau$ and $\theta_\tau$
are learned afresh for each task, with $I$ held fixed.

\subsection{Good solutions and structural transfer}
\label{sec:problem-formulation}

To judge a structure, we fit its numerical parameters on the support
sample using a specified optimizer, initialization rule, and budget
of $T$ updates. Let $\widehat f_{\tau,I}$ denote the resulting predictor.
For an error tolerance $\varepsilon$, we call it a \emph{good solution}
if its expected loss on new examples from the task is at most
$\varepsilon$:
\begin{equation}
    \mathcal{R}_\tau(\widehat f_{\tau,I})
    :=\mathbb{E}_{(x,y)\sim P_\tau}
    \left[\ell(\widehat f_{\tau,I}(x),y)\right]
    \leq\varepsilon.
    \label{eq:good-solution}
\end{equation}
The data available for fitting and the training budget are part of this
criterion: a structure is useful when its parameters can be learned
well under those conditions.

In practice, the expected loss is usually unknown, so we compare fitted
predictors using their query loss. When query data are used to select
a candidate, final performance is measured on additional test examples
unused in selection. We assess structural transfer across new tasks
and fresh initializations to determine how reliably the proposed
constraints lead to good solutions.

Several structures may support good solutions, and their usefulness
may vary across tasks. Our shared model is therefore a distribution
$Q_\phi(I)$ over indexators, with parameters $\phi$ learned from source
tasks. On a target task, this distribution is kept fixed and supplies
candidate structures. Each candidate receives newly trained numerical
parameters, and the query sample is used to select the resulting
predictor.
