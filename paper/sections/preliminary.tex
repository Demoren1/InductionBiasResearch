\section{Preliminary}
\label{sec:preliminary}

Related prediction tasks may benefit from the same relations between
weights even when they require different numerical values. For example,
a group of connections may share a coefficient in each task, while its
value changes from one task to another. Reusing this pattern constrains the
parameters learned on a new task. Such constraints can help a predictor
generalize from limited data and change which solutions an optimizer
finds within a given budget. We study this form of transfer by separating
the structure of a network from its numerical parameters. The structure
is proposed from experience with previous tasks; its usefulness is
judged after the numerical parameters have been learned anew.

\subsection{Multi-task learning}
\label{sec:tasks}

Multi-task learning uses regularities shared by related tasks to improve
learning. Here, each task $\tau$ is a supervised prediction problem with
its own distribution $P_\tau$ over input--target pairs $(\mathbf{x},y)$. Tasks
belong to a family $\mathcal{T}$, share input and target spaces
$\mathcal{X}$ and $\mathcal{Y}$, and occur according to a distribution
$p(\tau)$ \cite{baxter2000model}. We consider task families in which
structural patterns useful for solving one task may also help solve others.

We learn these patterns from source tasks $\mathcal{T}_{\mathrm{tr}}$
and assess their transfer on a disjoint collection of target tasks
$\mathcal{T}_{\mathrm{val}}$ drawn from the same task environment.
For each task, a \emph{support sample} $S_\tau^{\mathrm{s}}$ is used to
fit numerical parameters, and an independent \emph{query sample}
$S_\tau^{\mathrm{q}}$ is used to compare the fitted predictors
\cite{finn2017model,zhou2021meta}. Both consist of independent draws
from $P_\tau$. For a predictor $f$ and a sample $S$, the empirical loss is
\begin{equation}
    \mathcal{L}_S(f)
    :=\frac{1}{|S|}\sum_{(\mathbf{x},y)\in S}\ell(f(\mathbf{x}),y).
    \label{eq:task-loss}
\end{equation}
Here, $\ell$ measures prediction error on one example, such as squared
error for regression or cross-entropy for classification.

\subsection{Parameter sharing}
\label{sec:network-structure}

Parameter sharing assigns a single trainable value to a group of network
weights. Deep Compression represents such weights using a \emph{codebook}
of shared values and an index for each connection \cite{han2016deep}.
We use this representation to separate the pattern of shared parameters
from the numerical values learned for a particular task.

We fix a common network architecture and collect the weights subject to
these constraints into a vector $\mathbf{w}\in\mathbb{R}^{P}$. An integer array
$\mathbf{I}\in\{0,\ldots,K\}^{P}$ assigns each weight to an entry in the codebook
$\mathbf{C}_\tau=(C_{\tau,0},\ldots,C_{\tau,K})$. We call this array an
\emph{indexator}. The weights are given by
\begin{equation}
    w_p=C_{\tau,I_p},\qquad p=1,\ldots,P,\qquad C_{\tau,0}=0.
    \label{eq:indexator-weights}
\end{equation}
Connections with the same positive index therefore share one trainable
parameter. We reserve index $0$ for a fixed zero value, so that the same
representation also specifies which connections are absent. A binary
connectivity mask is the special case in which each active connection
has its own trainable codebook entry.

For the trainable weights, this is equivalent to the discrete assignment
representation of \citet{yeh2022equivariance}: each row of a binary
assignment matrix selects one shared numerical parameter. The indexator
records the selected column for each weight. Its positive labels simply
name groups; consistently renaming these labels and the corresponding
codebook entries preserves the sharing pattern.

For example,
$$
    \mathbf{I}=(1,2,1,0)
    \quad\Longrightarrow\quad
    \mathbf{w}=(C_{\tau,1},C_{\tau,2},C_{\tau,1},0).
$$
The first and third weights are tied, and the fourth is fixed at zero.
One task may learn $\mathbf{w}=(0.7,-1.2,0.7,0)$ and another
$\mathbf{w}=(-0.4,0.9,-0.4,0)$ under the same constraints. The transferable
structure is the assignment of connections to shared parameters;
the codebook supplies their values on each task.

We write $f_{\mathbf{I},\mathbf{C}_\tau,\boldsymbol{\theta}_\tau}$ for the resulting
predictor, where $\boldsymbol{\theta}_\tau$ contains any remaining trainable
parameters, such as biases. On a new task, we reuse only the proposed
indexator $\mathbf{I}$. In every fitting attempt, $\mathbf{I}$ is held fixed,
while all trainable entries of $\mathbf{C}_\tau$ and all of
$\boldsymbol{\theta}_\tau$ are initialized afresh and optimized
on the task's support sample. This also applies to repeated attempts
with the same indexator.

\subsection{Good solutions and structural transfer}
\label{sec:problem-formulation}

Let $\widehat f_{\tau,\mathbf{I}}$ be a predictor obtained by fitting numerical
parameters under structure $\mathbf{I}$. For a chosen error tolerance
$\varepsilon$, we call it a \emph{good solution} to task $\tau$ when
its expected loss on new examples satisfies
\begin{equation}
    \mathcal{R}_\tau(\widehat f_{\tau,\mathbf{I}})
    :=\mathbb{E}_{(\mathbf{x},y)\sim P_\tau}
    \left[\ell(\widehat f_{\tau,\mathbf{I}}(\mathbf{x}),y)\right]
    \leq\varepsilon.
    \label{eq:good-solution}
\end{equation}
The tolerance specifies the desired prediction quality. Whether training
reaches it also depends on the support data, optimizer, initialization
rule, and training budget. A structure may admit a good solution while
the numerical optimizer rarely finds it. We therefore assess structures
through the outcomes of actual fitting attempts under specified
conditions, including fresh initializations.

Several structures may support good solutions to a task, and useful
patterns may recur across tasks. Our shared learned object is a
distribution $Q_{\boldsymbol{\phi}}(\mathbf{I})$ over indexators. Source tasks
are used to learn its parameters $\boldsymbol{\phi}$. On a target task,
$\boldsymbol{\phi}$ is frozen and the model proposes candidate structures,
each of which receives fresh numerical
training. Successful transfer requires both proposing a suitable
structure and fitting its parameters well.

Since expected loss is usually unknown, we select among the fitted
predictors by their query loss and measure final performance on further
test examples unused in fitting or selection. We evaluate the resulting
procedure across new tasks and independent runs, accounting for all
candidate fits and restarts in the target-task training budget and
reporting source-task learning costs separately. The aim is to make good
solutions more reliably attainable with the available data and
computation; comparisons with dense optimization establish whether the
learned constraints provide that benefit.
