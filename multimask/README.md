# Синтетика с четырьмя равноценными масками

Два независимых семейства A/B позволяют проверить выбор структуры через `z`.
Каждая задача имеет четыре заранее известных Bayes-оптимальных маски с **32 связями**.
Другие равноценные реализации не исключаются: качество BCE важнее совпадения
с конечным набором эталонов. Эксперимент находится отдельно от `pattern`;
его код не изменён. Общие функции сериализации, NF-слой, checkpoint selection
и построение графиков импортируются из него без изменения.

## Данные и эталоны

Вход: `[A₀…A₃₁, A₀, A₁₆, B₀…B₃₁, B₀, B₁₆]`, всего 68 координат.
Исходные A/B — независимые равномерные ±1 биты; две дополнительные координаты
каждого семейства точно копируют исходные. Семейство A использует только A,
семейство B — только B. В каждом восемь непересекающихся блоков длины четыре.

Для паттерна `t` и блока `j`:

```text
h_j = ReLU(sum_r (2*t_r - 1)*s_(4*j+r) - 3)  # 1 при совпадении, иначе 0
p   = sigmoid(2*(sum_j h_j - 0.5))
```

Цель MLP — мягкая вероятность `p`; loss — обычная BCE без балансировки классов.
Её известный минимум на данной выборке: `BCE(p,p)`. Это ожидаемый Bernoulli-риск,
а не loss на одной шумной реализации меток. Accuracy отдельно измеряется
по детерминированной метке `p > 0.5`: встретился ли паттерн хотя бы в одном блоке.

Эталонная MLP имеет 8 ReLU-нейронов: по 4 входные связи на блок, веса ±1,
биасы −3, readout 2, выходной bias −1. Биты №0 и №16 можно независимо заменить
их копиями: варианты 0/1/2/3 означают ни одной замены, замену №0, замену №16,
обе замены. Они отличаются входными строками, поэтому перестановка скрытых
колонок не превращает их в одну маску. Это контролируемая неоднозначность
из-за дублирования входов, а не четыре разных алгоритма.

Каждая функция зависит от всех 32 логических битов своего семейства. Маска,
достигающая эталонного риска в обоих семействах, должна охватывать минимум
64 независимых бита; бюджет 32 исключает такое общее решение.

В каждом семействе train-паттерны: `0000, 0001, 0011, 0101, 0110, 1111`;
отложенные: `1001, 1010`. Всего **12 обучающих / 4 отложенные задачи**.
Общие непересекающиеся пулы: 1024 support, 256 query, 256 probe,
512 validation, 4096 test. `data.pt` содержит только входы; метки вычисляются
при использовании разрешённого пула. Метки отложенных задач впервые вычисляются
после записи зафиксированных кандидатных масок на диск.

## Банк и модель

По умолчанию **128 MLP на каждую из 12 train-задач**, всего 1536 карт.
Seed-разбиение карт: 96 train / 16 validation / 16 test на задачу.
Качество и IoU не используются для отбора сетей.

IMP начинает с плотного слоя `68×8`, удаляет 20% оставшихся связей по `|W|`
до ровно 32 и каждый раунд возвращает все параметры к исходной инициализации.
Adam создаётся заново. В раунде до 2000 шагов, lr=0.01, L2=0.
Инициализация: W ~ N(0,0.1²), hidden bias=0, readout=0.5, output bias=-1;
все эти параметры затем обучаются без ограничений. Первые 100 шагов каждого
раунда используют линейную активацию (LeakyReLU slope=1), затем обычную ReLU.
Разогрев помогает выйти из плохих локальных решений с ReLU.
Каждые 25 шагов выбирается собственный query-checkpoint каждой MLP.
Отбор checkpoint, все отчётные BCE, градиенты и функциональные карты всегда
вычисляются с конечной ReLU, включая период разогрева. Аналитические маски
и веса не участвуют в обучении или pruning.
Одновременно обучаются 64 независимые сети; их loss складываются,
поэтому градиент каждой соответствует отдельному обучению.

После последнего раунда сохраняются три канала: `W*mask`, градиент support BCE
по W без L2, функциональная карта `E_probe |x_i*d(psi_j)/dx_i|`.
Все входы имеют модуль 1, поэтому последний канал вычисляется через частоту
активации ReLU, без большого тензора `[networks,probe,rows,hidden]`.
Веса и каналы совместно сортируются по функциональному центроиду скрытых нейронов;
каждый канал нормируется отдельно по максимуму модуля.

Два NF-слоя → среднее по скрытым колонкам → VAE encoder у каждой задачи;
decoder общий. Размеры: NF8 / encoder64 / z16 / decoder128.
Loss: `0.8*weighted BCE + 0.2*hard-mask MSE + beta*KL`;
положительный вес mask BCE — `(544−32)/32=16`, beta=0.005 с разогревом за 30 эпох.
Hard top-32 использует straight-through sigmoid. AdamW: lr=0.001, wd=0.01,
batch=64 на задачу, до 100 эпох, patience=20.
Эти значения — начальный протокол, не результат подбора на новом датасете.

Лучший checkpoint выбирается по среднему максимальному IoU с четырьмя эталонами
на validation-картах обучающих задач. При равенстве выбирается меньший VAE loss.
Диагностические train/validation loss и KL вычисляются через `z=mu`
с одинаковым полным beta; фактический beta оптимизации записывается отдельно.

## Оценка

Два эпизода: шесть source-задач A → две отложенные A, затем аналогично B.
Decoder заморожен; восемь `z` стартуют из N(0,I), оптимизируются только они.
По умолчанию используется прямой поиск по BCE: в каждой из 100 итераций
на каждый restart предлагаются четыре `z` — два Gaussian-направления
и их противоположности, стандартное отклонение по координате 0.3.
Кандидаты оцениваются по настоящей средней source-query BCE после 512 шагов
свежего child SGD. Новый z принимается только при строгом улучшении BCE
своего restart. Внутренний SGD имеет lr=2.0.
Одинаковые бинарные маски оцениваются один раз в рамках эпизода: их BCE
при фиксированных данных и свежих seeds не зависит от конкретного z.
Граф внутреннего обучения не сохраняется для обратного прохода через z.
Для воспроизведения прежнего straight-through поиска доступен
`Z_METHOD=gradient`: 100 шагов Adam для z, `Z_LR=0.05`.
Инициализация и первые 100 линейных шагов совпадают с протоколом банка;
внешняя BCE вычисляется с ReLU. Такой внутренний fit дороже прежних 64 шагов.
Свежие Adam fits используют 1000 шагов и lr=0.01 с тем же разогревом.
Число шагов inner/child должно превышать MLP_WARMUP.
`Z_LR` используется только в gradient-режиме; `Z_RADIUS` и `Z_CANDIDATES` —
только в evolution. Эти три новых значения задаются также в evaluate.sh,
поэтому новый поиск работает с уже обученным `nf_vae_v3` без повторного train.
Для выбора restart выполняются свежие Adam fits на source-support;
query выбирает child-checkpoint, отдельная source-validation выбирает restart.

После фиксации масок отложенные MLP обучаются с трёх свежих инициализаций;
support обучает, query выбирает checkpoint, test только оценивает.
Ни z, ни decoder по отложенным меткам не обновляются.
Сиды child MLP одинаковы для сравниваемых масок, независимы между задачами/репликами.

Сравнения: оптимизированный z, все исходные случайные z, их среднее качество
и лучший случайный z, выбранный по той же source-validation без оптимизации,
частотная маска всех train-карт, частотная маска семейства, фиксированные A/B,
четыре эталона правильного семейства. Частотные маски используют только train-seeds
банка, в его каноническом порядке колонок; analytic alignment служит визуализации.
Свежие fits эталонов показывают трудность оптимизации, а `BCE(p,p)` — известный
теоретический ориентир независимо от того, удалось ли обучить свежую MLP.

Основные метрики: test BCE, превышение `BCE(p,p)`, accuracy, nearest-reference IoU,
доля точных масок и покрытие четырёх вариантов среди рестартов.
Сохранение одного равноценного варианта внутри семейства допустимо;
покрытие всех четырёх — отдельная диагностика разнообразия.

## Запуск

Используется существующее Python-окружение проекта: PyTorch, NumPy, SciPy,
Matplotlib, tqdm (`pip install -r pattern/requirements.txt`).
Скрипты запускаются из любого каталога; **MPS выбран по умолчанию**.

```bash
./multimask/sh_scripts/train.sh
./multimask/sh_scripts/evaluate.sh
```

`train.sh` автоматически собирает отсутствующий банк, затем обучает модель.
Первый обычный запуск собирает все 1536 карт. Полный новый банк пользователь
собирает самостоятельно; при подборе использовались отдельные маленькие пилоты.
Дефолты: `BANK=data/multimask/banks/imp32_128_mlp_v3`, `RUN_ID=nf_vae_v3`;
evaluate читает `RUN=multimask/runs/nf_vae_v3` и его сохранённый конфиг.
Старый банк `imp32_1024_v2` и run `nf_vae_v2` сохранены. Старые checkpoint
без настроек разогрева используют прежнюю инициализацию и обучение.
Для повторного обучения используй новый RUN_ID. Другой протокол банка требует
нового BANK: существующий или незавершённый банк не перезаписывается.

```bash
CONFIG=multimask/config.json RUN_ID=trial_2 EPOCHS=60 BETA=0.002 \
  ./multimask/sh_scripts/train.sh
RUN=multimask/runs/trial_2 Z_STARTS=16 Z_STEPS=150 REPLICAS=5 \
  ./multimask/sh_scripts/evaluate.sh
DEVICE=cpu ./multimask/sh_scripts/evaluate.sh --help
```

MAPS_PER_TASK (128), BANK_BATCH (64), BANK_STEPS (2000), BANK_LR (0.01),
BANK_L2 (0), MLP_WARMUP (100), BATCH_SIZE, LR, BETA,
DEVICE, THREADS, PROGRESS и LOG_DIR настраиваются через окружение.
Остальные настройки находятся в config.json; можно дописывать Python CLI-флаги
в конец команды. В evaluate доступны Z_METHOD (evolution/gradient), Z_CANDIDATES (4, чётное),
Z_RADIUS (0.3), Z_STARTS/Z_STEPS/Z_LR, INNER_STEPS/INNER_LR,
CHILD_STEPS/CHILD_LR, SELECT_EVERY, REPLICAS, LOG_EVERY, EVALUATION_ID.
`DEVICE=auto` выбирает доступный ускоритель; `DEVICE=cpu` — CPU.

## Подбор MLP и аудит от 13 октября 2026

В старом банке проверены все 12 288 карт: хеши, пулы и разбиения, бинарность
масок, ровно 32 связи, сохранённые support/query BCE, канонизация и нормировка
каналов. Градиенты и функциональные карты дополнительно пересчитаны для 48 MLP.
Ошибок хранения нет, но качество учителей низкое: средняя support BCE=0.6268,
query=0.6434, независимая source-validation=0.6436 при минимуме 0.5451;
средний IoU=0.3645, точных эталонных масок нет. Проблема обучения учителей
существеннее небольшого разрыва support/query.

Для подбора использовались только обучающие задачи. Контроль с известной маской
отделён от IMP, который начинает с плотной сети и не использует эталоны.
Проверены разные lr, L2, инициализации и длительности/активации разогрева.
После первого IMP-пилота (4 задачи × 8 инициализаций, 9 режимов)
подтверждение проведено на всех 12 source-задачах × 4 новых инициализациях,
с одинаковыми seeds для сравниваемых режимов. Настройки выбирались по query BCE;
независимая source-validation и IoU служат диагностикой. Отложенные четыре
задачи при подборе не использовались.

| Режим IMP | Шагов/раунд | Query BCE | Source-validation BCE | Средний IoU | Точных масок / 48 |
|---|---:|---:|---:|---:|---:|
| Прежний: случайный readout, ReLU, lr=0.03 | 1000 | 0.64366 | 0.64155 | 0.39071 | 0 |
| Новый: readout=0.5, linear→ReLU, lr=0.01 | 1000 | 0.56902 | 0.56726 | 0.84772 | 7 |

Рабочий сборщик дополнительно проверен на 48 картах (по 4 на все 12 задач),
с последующим обучением NF/VAE в течение одной эпохи и проверкой градиента z.
Свежие Adam fits всех четырёх эталонных масок на всех source-задачах достигли
аналитической BCE с погрешностью float32. Терминальный SGD с lr=2, 512 шагами
и 100 линейными шагами тоже достиг минимума на 12 задачах × 4 инициализациях
без выбора лучшего checkpoint. Это контроль обучения MLP; он не доказывает
сходимость поиска z. При сборе теперь выводятся query BCE, её аналитический
минимум и IoU каждой задачи.

Это лучшие настройки среди проверенных, а не доказанный глобальный оптимум.
Банк после IMP всё ещё содержит неоптимальные маски; они не фильтруются.
VAE и настройки его оптимизации сохранены. Низкая BCE учителей сама по себе
не гарантирует качество decoder или успешную оптимизацию z.

## Диагностика поиска z от 13 октября 2026

В `nf_vae_v3` decoder на source-posterior z семейства B выдаёт точные маски
(IoU=1); новый банк не мешает представлению правильной структуры. Прежний
straight-through поиск ухудшал среднюю source-query BCE B с 0.63477 до 0.69797;
выбранный restart остался на шаге 0. Проверка первого направления показала:
шаг по surrogate-градиенту с lr=0.05 ухудшал BCE до 0.63961, противоположный
шаг давал 0.63357. Даже малые шаги 0.001–0.01 часто ухудшали BCE.
Градиент sigmoid-релаксации не описывает скачки настоящего top-32 objective;
поэтому заменена стратегия поиска, без изменений банка и весов decoder.

Радиус подбирался на шести source-задачах каждого семейства, с восемью
одинаковыми N(0,I)-стартами, четырьмя предложениями на restart и 60 итерациями.
Критерий — source-query BCE; source-validation отдельно выбирает restart.
Отложенные задачи в подборе не использовались.

| Радиус | Средняя итоговая query BCE A | Средняя итоговая query BCE B | IoU выбранной маски A / B |
|---|---:|---:|---:|
| 0.05 | 0.59155 | 0.60179 | 0.82857 / 0.93939 |
| 0.15 | 0.57163 | 0.57944 | 0.77778 / 1.00000 |
| 0.30 | 0.56196 | 0.57100 | 1.00000 / 1.00000 |

Итоговая проверка рабочего evaluate (100 итераций, существующий `nf_vae_v3`):

| Семейство | IoU выбранной маски | Test BCE | Excess BCE | Accuracy |
|---|---:|---:|---:|---:|
| A | 1.00000 | 0.54858 | ≈0 | 1.00000 |
| B | 1.00000 | 0.54540 | ≈0 | 1.00000 |

Артефакты: `runs/nf_vae_v3/evaluations/z_evolution_20261013` (локально, вне Git).
Декодер и банк не изменились; параметры зафиксированы до итоговой оценки.

В истории поиска сохраняются BCE всех рестартов, число принятых предложений
и число оценённых уникальных масок. В итоговых метриках записаны метод поиска,
шаг выбранного z и факт изменения маски относительно исходного z.
Принятые query BCE каждого restart в evolution не возрастают; улучшение
на других seeds, validation или отложенных данных этим не гарантируется.
