# Перенос W/G-масок между функциями с общей структурой

Рабочая реализация эксперимента со скрытыми группировками. Организация
аналогична `pattern`: отдельные модели, банк, конфиги, обучение и оценка.
[Финальный отчёт за 20 октября](../mds/FINAL_REPORT_2026-10-20.md)
содержит математическую постановку, результаты и графики.

У учителя 48 независимых входов и восемь ReLU-нейронов. Маска содержит
32 связи: 16 общих и 16 зависящих от семейства. Последние 16 входов шумовые.
Внутри семейства функции имеют одинаковую маску, но разные веса, пороги
и выходные коэффициенты. Сеть без маски — одна MLP 48→8→1, 401 параметр.

## Код

| Модуль | Назначение |
| --- | --- |
| `problem.py`, `masks.py` | Семейства, учитель, наблюдения, маски и метрики |
| `models/task.py` | Обучение независимых MLP одной большой матрицей и IMP с rewind |
| `bank/collect.py`, `bank/features.py` | Возобновляемый сбор W/G-банка на нескольких GPU |
| `datasets.py`, `models/vae.py`, `train.py` | Независимые NF-энкодеры функций и один общий декодер |
| `search.py`, `evaluate.py` | Fitness, поиск z и оценка после фиксации масок |
| `launch.py`, `runtime.py` | Общая очередь процессов и ограничения CUDA-памяти |
| `tune.py` | Подбор внутреннего обучения на фиксированных калибровочных семействах |
| `reporting/` | Сводки, диагностика, сравнение и хитмапы из готовых результатов |
| `io.py`, `configs/` | Атомарная запись, хеши, снимки исходников и настройки |

Все обучения и извлечение градиентов выполняются на CUDA. CPU используется
для генераторов случайных чисел, дискретного сопоставления колонок и графиков.
Банк хранит эффективные веса первого слоя W, градиент support BCE G,
маску IMP, состояния сетей, наблюдения и диагностические метрики.
Функциональные пробы и AGOP не собираются и не подаются энкодеру.
Колонки W/G и целевой маски переставляются совместно по бинарным профилям
самой IMP-маски; аналитическая маска для этого не нужна. Сопоставление
в reconstruction учитывает перестановки колонок независимо от этого порядка.

Новый формат банка — `overlapping-groups.wg.v2`. Старый банк v1 доступен
для чтения W/G; дополнительные исторические поля не используются.
Возобновлять сбор старого банка новым сборщиком нельзя: для v2 нужен новый
каталог. Декодер не изменён и загружает прежние W/G-чекпойнты. Энкодер
упрощён: удалена нулевая ветка AGOP, поэтому старое полное состояние VAE
не предназначено для продолжения обучения в новой архитектуре.
Исторические результаты в отчёте получены до этой очистки.

## Команды

Запускать из корня репозитория в окружении с PyTorch CUDA, NumPy, SciPy
и Matplotlib. Банки по умолчанию находятся в `data/overlapping_groups/banks/`,
запуски — в `overlapping_groups/runs/`; оба каталога исключены из Git.
Ни импорт, ни `--help` не запускают обучение.

Сбор нового банка: 24 обучающих и восемь валидационных семейств, по четыре
функции, 128/32 MLP на функцию; всего 13 312 сетей. Обучающие роли разделены
96/16/16. Группировка сохраняет независимые функции потерь каждой сети.
Лимит 512 — число MLP с учётом дополнения неполных групп до общей ширины.
Лимит 12 GiB действует на один процесс GPU, включая резерв CUDA 2 GiB;
у сборщика по одному процессу на GPU.

```bash
python3 -m overlapping_groups.bank.collect \
  --bank data/overlapping_groups/banks/wg_v2 \
  --models-per-gpu 512 --gpu-memory-gib 12
```

Для продолжения совместимого незавершённого сбора добавить `--resume`.
Обучение трёх W/G-декодеров на новом банке:

```bash
python3 -m overlapping_groups.launch --phase train \
  --bank data/overlapping_groups/banks/wg_v2 \
  --runs overlapping_groups/runs/vae_v2
```

Поиск с уже готовыми старыми W/G-декодерами, без нового сбора и обучения VAE:

```bash
python3 -m overlapping_groups.launch --phase evaluate \
  --bank tmp/overlapping_groups_20261020/banks/bank_v1 \
  --vae-runs tmp/overlapping_groups_20261020/runs/vae_v1 \
  --runs overlapping_groups/runs/known_mask_v3 \
  --cache-from tmp/overlapping_groups_20261020/runs/known_mask_v1 \
  --workers-per-device 4 --gpu-memory-gib 8
```

Для нового банка указать его путь и `--vae-runs overlapping_groups/runs/vae_v2`,
убрать `--cache-from`. Число процессов и память задаются отдельно: при четырёх
процессах лимит 8 GiB относится к каждому процессу, а не к GPU целиком.
Везде можно ограничить устройства через `--devices cuda:0,cuda:1`.
`--families 0 1` ограничивает оценку; `--seeds 4213` выбирает один декодер.

Настройки по умолчанию зафиксированы после подбора: внутренний Adam,
64 шага, lr 0,1, warmup 32; внешний поиск — восемь стартов и 40 шагов,
бюджет 1608 кандидатов. Для изменения использовать копию конфигурации
через `--config`. Функции 0–3 входят в обучение VAE, 4/5 выбирают маску,
6/7 впервые читаются после её фиксации. Функции 8–11 не используются.
Выбор из IMP-банка оценивает кандидатов по query BCE функций 4/5,
без обращения к эталонной маске. Его пул сбалансирован по обучающим семействам,
содержит только train-роли и имеет тот же бюджет, что поиск z.

`--cache-from` переносит только наблюдения и фиксированный пул IMP-масок.
Старые IMP-оценки не переиспользуются: их протокол содержит хеш прежней
реализации MLP. Исходные банки, декодеры и завершённые запуски не меняются.
Если протокол или исходники отличаются, требуется новый каталог результата.

Повторный подбор внутреннего обучения (фиксированные семьи 0,3,6,…,21;
только функции 4/5), используя пул из существующего запуска:

```bash
python3 -m overlapping_groups.tune \
  --bank tmp/overlapping_groups_20261020/banks/bank_v1 \
  --cache tmp/overlapping_groups_20261020/runs/known_mask_v1 \
  --root overlapping_groups/runs/fitness_tuning_v2
```

Победивший конфиг сохраняется в `selected_config.json`. Аналитические маски
используются для калибровки и послепоисковой диагностики; они не доступны
алгоритму выбора маски. В итоговом сравнении отдельно учитывать восемь
калибровочных семейств и остальные семьи, как сделано в финальном отчёте.

## Графики без обучения

После запуска диспетчер оценки автоматически пишет сводку и основные
графики. Их также можно перестроить отдельно:

```bash
python3 -m overlapping_groups.reporting.summary \
  overlapping_groups/runs/known_mask_v3 \
  --bank tmp/overlapping_groups_20261020/banks/bank_v1

python3 -m overlapping_groups.reporting.audit \
  overlapping_groups/runs/known_mask_v3 \
  --bank tmp/overlapping_groups_20261020/banks/bank_v1

python3 -m overlapping_groups.reporting.diagnosis \
  overlapping_groups/runs/known_mask_v3

python3 -m overlapping_groups.reporting.figures \
  overlapping_groups/runs/known_mask_v3 \
  --bank tmp/overlapping_groups_20261020/banks/bank_v1 \
  --decoder-run tmp/overlapping_groups_20261020/runs/vae_v1/wg_4213 \
  --seed 4213 --families 0 22
```

Последняя команда показывает аналитическую маску, плотную MLP, одиночный
и средний IMP, декодер до/после поиска z и остальные методы. Пара до/после
использует один и тот же выбранный старт; аналитическое выравнивание колонок
производится только для рисунка. Декодирование для графиков работает на CPU.

Исторические протоколы, компактные результаты и рисунки сохранены в
[архиве](../tmp/overlapping_groups_20261020/README.md). Разовые пилоты,
проверки AGOP и старые отдельные диспетчеры удалены из рабочего кода.


## Композиционный пилот

Конфиги `composition_bank.json`, `composition_vae.json` и
`composition_transfer.json` задают шесть вариантов каждого из двух блоков.
24 сочетания входят в обучение, шесть новых сочетаний — в валидационный
пилот, ещё шесть оставлены для будущего test. Каждый отдельный блок
встречается в четырёх обучающих сочетаниях. Новая маска полностью
собирается из частей двух обучающих, при этом целиком отсутствует в train.
Генератор сохраняет родителей только как диагностическую информацию;
поиск получает наблюдения, замороженный декодер и общий train-пул IMP.

В отличие от `known_mask`, режим `composition` разрешает оценку только
на новых валидационных сочетаниях и проверяет, что VAE обучен ровно
на train-сочетаниях. Сборщик с `--source-only` не обучает IMP-банк
для валидационных и итоговых сочетаний.

Команды выполненного пилота на физических GPU 1 и 2:

```bash
python3 -m overlapping_groups.bank.collect \
  --bank data/overlapping_groups/banks/composition_pilot_v1 \
  --config overlapping_groups/configs/composition_bank.json \
  --source-only --train-count 16 --devices cuda:1,cuda:2 \
  --models-per-gpu 512 --gpu-memory-gib 12

python3 -m overlapping_groups.launch --phase train \
  --bank data/overlapping_groups/banks/composition_pilot_v1 \
  --config overlapping_groups/configs/composition_vae.json \
  --runs overlapping_groups/runs/composition_pilot_v1/vae \
  --devices cuda:1,cuda:2 --seeds 4213 4214 4215 4216 \
  --workers-per-device 2 --gpu-memory-gib 14

python3 -m overlapping_groups.launch --phase evaluate \
  --bank data/overlapping_groups/banks/composition_pilot_v1 \
  --vae-runs overlapping_groups/runs/composition_pilot_v1/vae \
  --runs overlapping_groups/runs/composition_pilot_v1/evaluation \
  --config overlapping_groups/configs/composition_transfer.json \
  --devices cuda:1,cuda:2 --seeds 4213 4214 4215 4216 \
  --workers-per-device 4 --gpu-memory-gib 8
```

Дополнительный контроль `recombined_bank` случайно выбирает две
train-маски IMP, сопоставляет колонки по их пересечению и берёт четыре
колонки из каждой. Если число связей отличается от 32, оно корректируется
внутри объединения родителей. Адаптационная query BCE выбирает кандидата
из 1608 вариантов; аналитическая маска и её родители не используются.
Это эвристический контроль сборки, а не полный поиск всех подмасок
в объединениях. Его успех или неуспех нужно отличать от выразительности
самого множества объединений.

Рисунки сборки и сравнения воспроизводит модуль
`overlapping_groups.reporting.composition`. Численные результаты и
[отчёт пилота](../mds/COMPOSITION_PILOT_2026-10-20.md) хранятся отдельно
от первого опыта с известными полными масками.
