# Pattern: IMP → веса, градиенты и функциональные карты → NF/VAE

Эксперимент проверяет, может ли модель по весам, градиентам и функциональному описанию обученной
сети восстановить её разреженную связность и получить структуру, близкую к
теплицевой. Для каждой pattern-задачи собирается собственный банк сетей и
обучается собственный блок из двух NF-слоёв и VAE encoder. Один decoder общий
для всех задач. IMP и предсказание decoder всегда оставляют **ровно 32 связи**
в первом слое `11×8`. Это 36,36% связей; удаляются 56 из 88.

## Задачи и данные

Входы — все 2048 бинарных последовательностей длины 11, представленные как ±1.
Каждая четырёхбитная строка задаёт задачу: метка 1, если строка встречается хотя
бы в одном окне последовательности. Базовый конфиг задаёт 12 train-задач в `tasks` и четыре отложенные в
`test_tasks`: `0010`, `0100`, `1011`, `1101`. Для них не собираются карты и не
обучаются encoder; их метки доступны только в заключительной оценке фиксированной маски. Матрица связности имеет 11 входных позиций и 8 скрытых нейронов.
Сеть-источник — `aᵀ ReLU(x(W⊙M)+b)+c`.

Наблюдения один раз делятся по seed: 768 support, 256 source query, 128 probe,
384 резервных validation и 512 test. Подобранный режим использует все 768
support-примеров и BCE с балансировкой классов; source query фиксирована для задачи.
Probe не использует меток. IMP использует support для градиентов, а 64 query-примера
выбирают состояние с минимальным BCE каждые 25 шагов каждого раунда. При поиске `z` используются support/query только 12 train-задач. Резервные
validation-наблюдения этих же 12 задач выбирают лучший restart. После выбора
маски на четырёх отложенных задачах обучаются свежие сети на support, а итоговые
BCE/accuracy измеряются на 512 test-наблюдениях. `z` и decoder на этом этапе неизменны.

Сети банка разделяются на train/validation/test **по network seed**, заранее,
без отбора по query-качеству. В текущем банке 1000 сетей на задачу: 750/125/125; всего 12 000 карт.
Все сохраняются, включая неудачные; это позволяет увидеть качество источников.
Данные разных задач используют одинаковое разбиение наблюдений, но разные метки.

## IMP

Обучаем dense-сеть, удаляем 20% оставшихся входных связей с наименьшими `|W|`,
возвращаем все численные параметры к исходной инициализации и обучаем заново.
Adam тоже создаётся заново. Последнее прореживание останавливается на 32 связях,
после чего сеть снова обучается с этой маской. Для стандартного коэффициента
плотности: `88 → 71 → 57 → 46 → 37 → 32`. Биасы и выходной readout не прореживаются
и не входят в бюджет 32. Порядок при равных величинах весов фиксирован.

Это выбранная реализация IMP с возвратом к инициализации, основанная на
[The Lottery Ticket Hypothesis](https://arxiv.org/abs/1803.03635). Возврат к более
позднему checkpoint здесь не реализован. По умолчанию каждый этап выполняет
1000 шагов; короткий smoke-конфиг проверяет только исполнение, а не сходимость.
Обученные веса предыдущего этапа используются для выбора связей, затем
выбрасываются: следующая разреженная MLP обучается с исходной инициализации.
Три входных канала собираются только после последнего обучения с 32 связями.

Скрипт запускает сбор пакетами по 256 независимых MLP одной задачи одновременно: веса имеют
форму `[networks,11,8]`, входы — `[networks,support_rows,11]`. Инициализация,
маска и моменты Adam отдельные у каждой сети; support-пул общий. BCE усредняется
по наблюдениям каждой сети, а для backward складываются её BCE и L2 с loss
остальных сетей; градиенты не делятся на число сетей. Прореживание выполняется
отдельно для каждой матрицы, с возвратом к её исходной инициализации.
Размер пакета задаётся `BANK_BATCH_SIZE=256` в `train.sh` или
`--network-batch-size 256` у сборщика. Прогресс показывает шаги внутри этапа IMP;
строки `N/1000` отмечают последующее сохранение готовых сетей.

## Функциональное представление

Для каждого probe-входа сохраняются вклад скрытого нейрона
`ψ_j(x)=a_j ReLU(u_j(x))` и производное по входной координате представление
`q_ij(x)=x_i (W_ij M_ij) a_j 1[u_j(x)>0]`.

На вход NF идут три канала в фиксированном порядке:

1. `weights`: итоговые веса первого слоя `W⊙M` разреженной MLP;
2. `loss_gradient`: `d(class-balanced BCE_support)/dW` в выбранном итоговом состоянии;
3. `functional_map`: `E_probe[|q|]` от той же итоговой сети.

Градиент считается по support-примерам с той же балансировкой классов, без L2-штрафа.
Маска фиксирована в графе `W⊙M`, поэтому выключенные связи имеют нулевые веса
и нулевой градиент. Query, validation и test-наблюдения в этот градиент не входят.
Сохраняем именно градиент итогового состояния, пересчитанный после обновления
весов, а не градиент перед последним шагом оптимизатора. Расчёт на копии W
не меняет обученную сеть.

`nf_features.pt` содержит исходные три матрицы `11×8`, имена каналов, support BCE
и ID наблюдений. Загрузчик совместно переставляет их столбцы и нормирует каждый
канал отдельно на `max(abs(channel))`, ограниченный снизу `1e-8`. Итоговый вход
NF имеет форму `[batch,11,8,3]`; знак весов и градиентов сохраняется. Бинарная
IMP-маска остаётся целью decoder, отдельным входным каналом она не служит.
Полные ψ и все варианты q сохраняются в `functional_map.pt` для анализа.

Новый банк имеет схему `pattern.imp_bank.v2`; состав каналов, источник градиента
и нормировка записаны в `manifest.json`, а все файлы защищены контрольными суммами.
Банки v1 с прежними каналами q загрузчик отклоняет. Нужно собрать новый банк
с новым ID и заново обучить NF/VAE; существующие банки и веса не перезаписываются.

Скрытые колонки карт и целевой маски одновременно сортируются по центроиду
`E|q|` на упорядоченных входных координатах. При совпадении центроидов используется
лексикографическое сравнение функциональных профилей. Полностью совпавшие
профили, например неактивных нейронов, не позволяют однозначно восстановить
порядок разных масок; в этом случае остаётся исходный порядок. Это явно заданное правило
препроцессинга; оно не является выученным обнаружением порядка.

## Модель и обучение

```text
веса / градиент BCE / функциональная карта [11,8,3]
  → NF layer → GELU → NF layer → GELU       отдельные параметры каждой задачи
  → mean по скрытым колонкам
  → VAE encoder → μ, log σ²                отдельные параметры каждой задачи
  → z = μ + σ ε
  → shared decoder → logits [11,8]         одна общая модель
  → hard top-32 → бинарная маска
```

NF реализованы как специализация для одного функционального тензора:
`y_j = A x_j + B mean_k(x_k) + b`, где `x_j` содержит все входные координаты
одного скрытого нейрона. Матрицы A/B общие для скрытых колонок; входные позиции
сохраняют свой порядок. Каждый слой эквивариантен к перестановке скрытых нейронов,
а VAE encoder после mean-pooling инвариантен. Это адаптация принципа
[Permutation Equivariant Neural Functionals](https://arxiv.org/abs/2302.14040),
а не полная реализация общего NF для параметров многослойной сети.

Loss: `(1−α) weighted BCE(logits, IMP mask) + α MSE(hard mask, IMP mask) + β KL`.
По умолчанию `α=0.2`, положительный вес BCE — `56/32`, `β=0.005` с разогревом
за 30 эпох. Размеры модели: NF 8, encoder 64, latent 16, decoder 128.
AdamW использует lr=0.001 и weight decay=0.01; batch=128 на задачу.
Подобранный бюджет — 5 эпох, по 6 обновлений на эпоху. Разогрев начинается с
малого β: на пятой эпохе фактически используется β=0.0008333. Hard top-32 в прямом проходе всегда бинарен; для MSE используется
straight-through градиент sigmoid. BCE действует непосредственно на logits.
Градиенты общей модели усредняются по задачам, чтобы каждая имела одинаковый вес.

Checkpoint выбирается по максимальному среднему IoU с аналитической теплицевой
маской после оптимальной перестановки скрытых столбцов на validation-сетях банка.
При одинаковом IoU выбирается меньшая VAE loss. Это выделение общей структуры:
восстановление индивидуальных IMP-масок служит дополнительной диагностикой.
При диагностике восстановления validation/test сетей банка используют
детерминированный `z=μ`. Четыре отложенные pattern-задачи не участвуют в выборе
checkpoint. Лучшие encoder и единственный decoder сохраняются отдельно.

## Запуск

Команды выполняются из корня проекта. Требуются Python ≥3.10, PyTorch ≥2.0,
NumPy, Matplotlib, SciPy и tqdm; зависимости перечислены в `pattern/requirements.txt`.
Конфиги JSON читаются стандартной библиотекой, дополнительных зависимостей нет.

Скрипт обучения автоматически собирает отсутствующий банк, затем запускает обучение:

```bash
bash pattern/sh_scripts/train.sh
bash pattern/sh_scripts/evaluate.sh
```

Можно запустить `./train.sh` из `pattern/sh_scripts` без указания банка:
по умолчанию используется `data/pattern/banks/imp32_fullsupport_1000_20261009`
с конфигом `pattern/configs/tuned.json`. Run по умолчанию — `nf_vae_v2`; evaluate
читает `pattern/runs/nf_vae_v2`. Для повторного обучения задай новый `RUN_ID`,
а при оценке укажи соответствующий `RUN`. Готовый банк читается
повторно; незавершённый или несовместимый банк вызывает ошибку. Для другого
протокола `CONFIG` укажи новый путь `BANK`. Сбор использует тот же `CONFIG`,
`DEVICE` и `THREADS`, что и обучение, и попадает в общий лог запуска.
Банк можно собрать отдельно: `python data/collect_pattern_maps.py --config pattern/configs/tuned.json --bank-id NEW_BANK_ID --device auto --network-batch-size 256`.

`auto` сначала выбирает MPS — ускоритель Mac, затем CUDA и CPU. Можно явно
указать `mps`, `cpu` или `cuda:0`. MPS должен быть доступен в установленной
сборке PyTorch; [описание MPS](https://docs.pytorch.org/docs/stable/notes/mps.html). Сбор и обучение работают на одном устройстве за запуск. Текущий
сборщик не принимает прежние аргументы mixed-density-банка: его заменил IMP.

Если ID не указан, создаётся имя с UTC-временем и случайным суффиксом.
**Существующий банк, run или evaluation не перезаписывается.** Банки лежат под
`data/pattern/banks`, веса моделей и предсказания — под `pattern/runs`. Каждая
карта, маска, состояние и история имеют контрольную сумму; изменение банка
обнаруживается при чтении. Неудачный сбор остаётся со статусом `running` и не
принимается для обучения; для повторения нужен новый ID.

Короткая проверка всей цепочки:

```bash
python data/collect_pattern_maps.py --config pattern/configs/smoke.json --bank-id smoke_imp32 --device cpu
python -m pattern.train --config pattern/configs/smoke.json --bank data/pattern/banks/smoke_imp32 --run-id smoke_nf_vae --device cpu
python -m pattern.evaluate --run pattern/runs/smoke_nf_vae --z-starts 2 --z-steps 2 --inner-steps 2 --child-steps 2 --replicas 1 --support-count 32 --query-count 16 --device cpu
python -m unittest discover -s pattern/tests -v
```

## Поиск z и итоговый тест

Режим по умолчанию — `MODE=latent`. Загружаем лучший checkpoint, замораживаем
shared decoder и инициализируем восемь независимых `z ~ N(0,I)`. Один `z`
задаёт одну общую маску для всех задач: decoder не имеет task condition.

На каждом внешнем шаге для каждой маски заново инициализируем 12 дочерних сетей
и обучаем их на source support с этой маской (64 шага SGD, lr=0.2).
Затем считаем обычную BCE на source query, усредняем по 12 задачам и обновляем
**только z** внешним Adam (100 шагов, lr=0.05). Внутренние веса — временные
параметры свежих сетей, они не изменяют checkpoint. Градиент в z проходит через
обучение дочерних сетей: используется
[`torch.autograd.grad(create_graph=True)`](https://docs.pytorch.org/docs/2.14/generated/torch.autograd.grad.html).
Forward-маска всегда бинарна и содержит ровно 32 связи; для её градиента
используется straight-through sigmoid. Во внешнем loss нет KL, штрафа за
теплицевость или сравнения с IMP-маской.

Для каждого старта сохраняем z с наименьшей source-query BCE. Эти кандидаты
проверяем на 12 source-задачах с новыми весами дочерних сетей: по три повтора,
до 1000 шагов Adam, lr=0.03 и L2=0.001 на всех 768 support-примерах
со сбалансированной BCE. Каждые 25 шагов query-BCE выбирает состояние каждой
дочерней сети; резервные validation-примеры не участвуют в этом выборе. Выбираем старт по средней BCE на резервных source
validation-наблюдениях. Маска сохраняется в `selected_mask.pt` **до чтения меток
четырёх отложенных задач**. Ни подбор z, ни выбор старта не используют их loss.

Заключительный тест обучает свежие сети на четырёх отложенных задачах с уже
выбранной общей маской. Для сравнения используется аналитическая маска с
парными начальными весами, тем же бюджетом и тремя повторами. Test-метки нужны
только для конечных BCE/accuracy; отдельные 64 query-примера выбирают
checkpoint дочерней сети, а 512 test-примеров в выборе не участвуют; не происходит обратного прохода в z или decoder.
Численные веса этих свежих сетей обучаются, маски остаются фиксированными.

Артефакты оценки:

- `protocol.json`: задачи, параметры, checkpoint, ID source-наблюдений;
- `latent_history.json`, `losses.csv`, `losses.png/pdf`: BCE по шагам каждого старта;
- `latent_codes.pt`, `selection.json`, `selected_mask.pt`: начальные/лучшие z, выбор
  по source validation, маска с 32 связями;
- `selection_losses/` и `test_losses/`: истории BCE обучения дочерних сетей,
  CSV и графики;
- `generated_masks/latent_search.pt`: начальные и конечные маски всех стартов,
  аналитическая маска, выровненные версии и перестановки;
- `heatmaps/latent_search.png/pdf`, `latent_search_values.pt`: аналитическая,
  начальная и выбранная маски, частоты связей по стартам;
- `metrics.json`: BCE/accuracy по четырём задачам и повторам, средние результаты,
  теплицевость исходной и выровненной маски; `COMPLETE.json` отмечает успешное завершение.

Аналитическая маска — четыре диагонали `0≤i−j<4`, ровно 32 связи. Она общая для
всех pattern-задач, поскольку описывает геометрию окон. Каждая маска отдельно
выравнивается с ней перестановкой скрытых колонок через задачу назначения.
Порядок входных позиций фиксирован. Выравнивание используется только в рисунках
и отдельных структурных метриках; BCE и выбор старта используют исходную маску.
Аналитическая маска не является BCE-целью обучения и не участвует в выборе z;
она используется как основной структурный критерий выбора checkpoint гипермодели.

## Настройки для M4 Pro, 48 ГБ

Bash-скрипты работают из любой директории. Параметры можно изменять в начале
скрипта, через переменные окружения или дополнительными аргументами Python CLI.
Относительные пути разрешаются от корня проекта. `DEVICE=auto` предпочитает MPS;
также доступны `DEVICE=cpu` и `DEVICE=mps`. `THREADS=1`, `PROGRESS=1`,
`PYTHON=python3`. `PROGRESS=0` отключает индикаторы.

```bash
bash pattern/sh_scripts/train.sh
bash pattern/sh_scripts/evaluate.sh

# Изменить бюджет поиска и число независимых стартов:
RUN=pattern/runs/nf_vae_v2 Z_STARTS=16 Z_STEPS=200 INNER_STEPS=128 \
CHILD_STEPS=1000 REPLICAS=5 bash pattern/sh_scripts/evaluate.sh
```

Train-параметры: `CONFIG`, `BANK`, `BANK_BATCH_SIZE=256`, `RUN_ID=nf_vae_v2`, `EPOCHS=5`, `BATCH_SIZE=128`,
`LR=0.001`, `BETA=0.005`, `KL_WARMUP_EPOCHS=30`, `HARD_LOSS_WEIGHT=0.2`,
`NF_CHANNELS=8`, `LATENT_DIM=16`, `ENCODER_WIDTH=64`, `DECODER_WIDTH=128`,
`OPTIMIZER=adamw`, `WEIGHT_DECAY=0.01`, `INITIALIZATION_SEED=4113`,
`SELECTION_METRIC=aligned_iou`, `PATIENCE=60`.
При пользовательском `CONFIG` его собственные значения сохраняются, если
переменные окружения не заданы. `BANK` принимается первым позиционным аргументом.

Eval-параметры: `RUN`, `EVALUATION_ID`, `MODE=latent`, `Z_STARTS=8`, `Z_STEPS=100`,
`Z_LR=0.05`, `INNER_STEPS=64`, `INNER_LR=0.2`, `SUPPORT_COUNT=768`, `QUERY_COUNT=64`,
`CHILD_STEPS=1000`, `CHILD_LR=0.03`, `REPLICAS=3`, `LOSS_LOG_EVERY=10`,
`SUPPORT_SAMPLING="all support observations"`, `SUPPORT_LOSS="class-balanced BCE"`,
`CHILD_L2=0.001`, `CHILD_SELECT_EVERY=25`.
`RUN` принимается первым позиционным аргументом. Все шаговые бюджеты latent-режима
должны быть положительными. Все кандидаты, задачи и повторы дочерних сетей
считаются батчем, чтобы уменьшить накладные расходы Metal.

Короткий замер до рефакторинга на этой машине (Apple M4 Pro, 48 ГБ, PyTorch 2.14.0, один CPU thread;
прогрев перед измерением, синхронизация MPS, без файлового ввода/вывода):

| Работа | CPU | MPS |
| --- | ---: | ---: |
| NF/VAE, 12 задач, batch 32, одно обновление | 12.0 мс | 38.3 мс |
| NF/VAE, 12 задач, batch 96, одно обновление | 23.6 мс | 39.6 мс |
| Поиск z, 8 стартов, 64 внутренних шага, forward/backward | 110.9 мс | 43.9 мс |

На MPS batch 96 даёт около 29 тысяч карт/с против 10 тысяч у batch 32.
CPU для этой небольшой NF-модели быстрее; можно запустить train с `DEVICE=cpu`.
Для поиска z MPS оказался быстрее примерно в 2.5 раза. Это выбор по измеренной
скорости и практический стартовый бюджет, **не доказанный оптимум качества**:
сходимость и теплицевость нужно оценивать на полном банке, подбирая параметры
только по source-данным. Четыре отложенные задачи нельзя использовать для такого подбора.

После рефакторинга encoder остаются отдельными, а общий decoder получает один
батч всех задач. Карты и цели загружаются на устройство один раз; метрики
переносятся на CPU таблицей. Поиск z переиспользует неизменные начальные веса
дочерних сетей, создавая новый граф вычислений на каждом внешнем шаге.
Парное сравнение с предыдущей версией (`cd14756`), batch 96, 12 задач,
12 измерений после прогрева: MPS — 42.7 → 28.3 мс на обновление, CPU —
22.7 → 21.7 мс. Это время вычисления шага, без сохранения checkpoint и рисунков.
Поиск z с восемью стартами и 64 внутренними шагами на MPS: 42.7 → 42.1 мс.
Выходы модели и градиенты параметров проверены с допуском на округление;
source BCE, маски и градиенты z в этом сравнении совпали точно.

Пакетный сбор IMP сравнен с последовательным (`2002505`) на этой же машине:
128 MLP, 256 support-наблюдений у каждой, 32 связи, 40 шагов Adam, медиана
трёх замеров после прогрева и синхронизации MPS. CPU: 0.596 → 0.049 с;
MPS: 3.878 → 0.042 с (примерно в 93 раза быстрее). Это вычисление одного
этапа, без прореживания и сохранения файлов. На четырёх сетях проверены все
шесть этапов IMP по 100 шагов: маски совпали, максимальное отличие параметров
на MPS — `4.8e-7`. Изменение меток одной сети не меняет остальные сети пакета.

Прогресс показывает эпохи обучения, шаги поиска z, source-выбора и финального
обучения сетей. Console-лог сохраняется в `pattern/runs/launch_logs` (`LOG_DIR`
меняет путь), в том числе при ошибке. Bash возвращает ошибку Python.
В конце train сохраняются loss JSON/CSV/PNG/PDF, маски и выровненные хитмапы
лучшего checkpoint: `generated_masks/<task>.pt`, `heatmaps/<task>_{example,mean}.png/pdf`.
График `losses.png/pdf` содержит отдельную панель невзвешенной KL-дивергенции
для train и validation, усреднённой по задачам. Ещё одна панель показывает
вклад `β·KL` с полным β для обеих выборок. Train и validation здесь оцениваются
детерминированно через μ; фактические loss/β оптимизации сохранены отдельно как
`optimization_loss` и `optimization_beta`. Отдельная панель показывает IoU
с выровненной аналитической маской.
CSV сохраняет эти средние и KL каждой задачи. В latent-оценке используется
только BCE, поэтому её графики не содержат KL-штрафа.

## Диагностика восстановления карт

Прежняя оценка сетей банка доступна отдельно:

```bash
RUN=pattern/runs/nf_vae_wgf_v2 MODE=reconstruction CHILD_STEPS=0 \
bash pattern/sh_scripts/evaluate.sh
```

`SPLIT=test` здесь означает новые **network seeds тех же source-задач**.
Это не четыре отложенные pattern-задачи. Сохраняются F1/IoU восстановления,
структурные метрики, аналитические/IMP/сгенерированные/functional top-32 маски
и выровненные хитмапы, а также 128 масок из общего decoder prior. Нули
весов и функциональных карт могут раскрывать отсутствующие связи, поэтому высокий
reconstruction F1 сам по себе не доказывает перенос структуры.
