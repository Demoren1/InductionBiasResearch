# Авторегрессионный генератор индексаторов: Pattern

Реализация согласованного 1 ноября 2026 рецепта: хорошие исходные индексаторы →
выравнивание столбцов и кодов → обучение совместного распределения → предложения
фиксированных индексаторов → новый численный кодбук для каждой целевой задачи.
VAE служит отдельным сравнением и не входит в основной генератор.

## Модель

`model.py` реализует MADE: 88 категориальных позиций по пять значений, два скрытых
слоя ширины 256. Маски весов строго исключают зависимость предсказания индекса
от него самого и от последующих индексов. Обучается обычное невзвешенное
максимальное правдоподобие, 2000 обновлений Adam, batch 128. Состояние выбирается
по NLL исходных validation-сетей. Сэмплирование последовательно, температура 1.
Top-32, оконная геометрия и ёмкости групп в генераторе не задаются.

## Данные и два этапа

Источник — `pattern/runs/codebook_20261028_v4/`: 1536 отобранных IMP-сетей,
1152/192/192 train/validation/test по seed сетей, 12 исходных шаблонов. Это банк
из обучения плотных сетей с последующим magnitude pruning и извлечением tying,
а не банк случайных фиксированных индексаторов. Новый IMP-сбор не выполняется.
Скрытые столбцы заранее согласованы по исходным тренировочным маскам.

Извлечение v4 использовало четыре связи на столбец и четыре группы по восемь.
Группы найдены по профилям весов на исходных задачах; их номера глобально
переименованы по первому появлению в исходном consensus. Истинный индексатор
не участвует в обучении. Код группы каждой позиции уже задан препроцессингом;
генератор в этом банке главным образом моделирует наличие связей, а не открывает
заново произвольные группы повторений. Это ограничение эксперимента.

- `protocol.json`, `runs/autoregressive_20261101_v1`: первоначальная проверка
  на всём отобранном банке. Выяснилось, что качество исходных свободных весов
  не гарантирует качество соответствующего индексатора с семью численными
  параметрами.
- `bank_quality.py`: отдельно проверяет каждый из 1536 индексаторов на его
  исходной задаче, заново обучая семь чисел с четырёх стартов по 2048 шагов.
  Отбор состояний и стартов по balanced source-query BCE; используется исходное
  разбиение наблюдений, целевые шаблоны не участвуют. Это конечный численный
  поиск, не вычисление глобального минимума по кодбуку.
- `protocol_filtered.json`, `runs/autoregressive_20261101_v2`: повтор после
  source-only отбора BCE < 0,3; 187/24/26 индексаторов, все 12 исходных задач
  представлены в train. Порог выбран по исходной диагностике, не подбором по
  target. Поскольку v1 уже просмотрен, v2 — этап разработки. Для парного
  сравнения сохранены те же target-разбиение, инициализации и бюджеты.

## Сравнения и бюджет

Авторегрессия; независимые частоты каждой позиции; случайный целый индексатор
банка; одинаковые для всех позиций вероятности по общему гистограммному составу;
необученная авторегрессия; VAE с предложением и VAE с оптимизацией z; исходный
извлечённый consensus; плотные Adam и SGD; oracle с известным индексатором.
В частотах аддитивное сглаживание 0,01. Во всех структурных методах семь
численных параметров; VAE+z дополнительно учит 16 переменных z. Плотные методы
имеют 105 параметров. SGD без momentum, как в исходном Pattern-протоколе.

VAE перенесён из v4, не переобучается после фильтрации в v2. Он использует
top-32 при декодировании; AR и частоты такого ограничения не имеют. VAE+z —
адаптивный поиск, а не контроль только качества исходных предложений.

Четыре прежних отложенных шаблона: `0010`, `0100`, `1011`, `1101`. Новое
разбиение 2048 входов: 768 support, 256 query, 512 test, 128 probe и 384 резерв.
В каждом методе 32 старта на шаблон, 4096 полных support-обновлений. Настройки
чисел взяты из source-only tuning v4: кодбук Adam 0,1 / начальная норма 0,5;
плотный Adam 0,01; SGD 0,3. Query BCE выбирает состояния и старты каждые 64 шага.
Независимый test отдельно от полного домена, включающего обучающие наблюдения.
128 стартов — четыре задачи, не 128 независимых новых задач. Бюджет обновлений
и предъявлений совпадает; FLOPs, число переменных и исходные затраты различны.

В отдельной диагностике замороженные генераторы предлагают по 8192 структур.
Измеряются точные совпадения с эталоном с учётом перестановок, F1 связей и F1
пар связей, использующих один код. Это оценка структурного покрытия, не оценка
ошибки 8192 обученных моделей. Параллельно сохраняется вероятность одного
канонического исходного consensus; она не равна полной массе полезных структур.
Аналитический индексатор используется только в oracle и последующей диагностике.

## Воспроизведение

Из корня проекта; GPU доступен вне sandbox. В выполненном опыте использованы
свободные GPU 2 и 3. Перед новым запуском выбрать свободное устройство.

```bash
CUDA_VISIBLE_DEVICES=2 /home/udeneev-av/myvenv/bin/python -m pattern.autoregressive.run
CUDA_VISIBLE_DEVICES=3 /home/udeneev-av/myvenv/bin/python -m pattern.autoregressive.bank_quality
CUDA_VISIBLE_DEVICES=2 /home/udeneev-av/myvenv/bin/python -m pattern.autoregressive.run --protocol pattern/autoregressive/protocol_filtered.json
CUDA_VISIBLE_DEVICES=3 /home/udeneev-av/myvenv/bin/python -m pattern.autoregressive.report --run pattern/runs/autoregressive_20261101_v1
CUDA_VISIBLE_DEVICES=3 /home/udeneev-av/myvenv/bin/python -m pattern.autoregressive.report --run pattern/runs/autoregressive_20261101_v2
```

`run.py` не перезаписывает существующий выход. Для повторного эксперимента
сохранить протокол с новым `run`; для `bank_quality.py` заданы пути исходного
v1-аудита. Снимки кода и SHA-256 сохранены в каждом запуске. В артефактах есть
индексаторы, кодбуки, z, веса выбранных моделей, шаги, train/query loss и recall.
После завершения кривые `*_history.json` сжаты gzip без потери содержимого;
отчёт читает оба варианта. Манифест `history_storage.json` хранит SHA-256
исходных JSON и размеры. Снимки запусков сохраняют первоначальный код записи.
Отчёт и рисунки создаются из сохранённых результатов. Тесты не создаются и не
запускаются.
