# Методы поиска индексатора: текущий кандидат и прежний контрастный вариант

Подробное связное описание завершённого варианта, все определения, математический вывод и псевдоалгоритм находятся в [FINAL_REPORT.md, разделы1–6](FINAL_REPORT.md). Здесь сохранён прежний контрастный алгоритм G1–G4 и кратко описан текущий functional-prefix кандидат G19–G23. Ни один пока не доказан как новый лучший метод в общем классе задач. Общая запись W=A(I)C, blind finite-alphabet factorization, статистические проекции, whitening и F-тесты известны; алгоритмическое отличие и его пользу нужно подтверждать сравнением. Подробные выводы и границы приоритета — THEORY.md и LITERATURE.md.

## G1–G4: контрастный индексатор с направлениями кодбуков

Вход: несколько source-функций, размеры общей матрицы, **точное** число K непустых знаковых групп, бюджет ошибки alpha и заранее заданные увеличивающиеся объёмы данных. Истинные подключения, число активных весов, группировки и численные C недоступны.

```text
Для каждого зарегистрированного объёма наблюдений n:
    1. Разделить наблюдения каждой функции на независимые половины a и b.
       По градиенту в нуле и полной кривизне решить нормальные уравнения.
       Оценить масштабы ошибок из остатков. Не использовать teacher-веса.

    2. По половине a получить предварительный I_a обычным whitening-PCA.
       Для этого I_a точно обучить отдельный кодбук каждой source-функции.
       Ортонормировать столбцы матрицы кодбуков T × K: получить V_a.
       Аналогично получить V_b только по половине b.

    3. Для каждой позиции проверить нулевой профиль.
       Для каждой пары позиций проверить равенство и равенство с минусом:
           a → b: V_a задаёт направления, данные b — проверяемый контраст;
           b → a: V_b задаёт направления, данные a — проверяемый контраст;
           fallback: полный межзадачный контраст по всем наблюдениям.
       Учитывать covariance ошибок, включая связи координат одного выхода.
       Разделить alpha шага между тремя семействами по E² гипотез.

    4. Сохранить только неотклонённые отношения.
       Построить граф +e, −e и нулевого якоря, сохраняя инволюцию знаков.
       Если компонент ровно 2K+1 и их знаковая структура допустима:
           вернуть целочисленный I, остановиться.
       Иначе увеличить данные; при исчерпании бюджета вернуть «не определён».

На новой функции:
    Зафиксировать I. Все C обучить заново только на новом support.
    Исходные кодбуки, плотные веса и optimizer states не переносить.
```

Здесь нет мягкой смеси, которую в конце приходится превращать в другой forward через argmax. Предварительная спектральная структура лишь выбирает направления проверки. Окончательный индексатор получается из отношений графа; предварительные назначения не фиксируются в нём навсегда.

## Что именно обосновано

При linear Gaussian модели, общей неизвестной variance и верном точном K вероятность когда-либо выдать неверный I не выше alpha. Контрасты заранее определены, направления обучены на независимой части, бюджет ошибки распределён по всем взглядам на данные. Это контроль неверной выдачи, а не обещание сходимости при любом конечном n или доказательство достоверности для произвольной MLP.

Неверный предварительный I может потерять полезное направление, но не делает его независимую проверку ложноположительной автоматически. Если разные истинные коды имеют один и тот же профиль на всех source-функциях, число классов недостаточно: процедура должна продолжать сбор или воздержаться.

Если K — верхняя граница, нарушена noise-модель, неизвестны симметрии латентных нейронов или модель нелинейна по оцениваемым весам, эту точную гарантию переносить нельзя. Соответствующие расширения остаются отдельными исследовательскими задачами.

## G19–G23: индексатор из значений ReLU-функции

В текущем pilot наблюдается сумма H ReLU-нейронов с известными общими bias b>0 и readout1/sqrt(H). Заданы D/H/точное K, неизвестны подключения, равенства, знаки и численные C. Выбирается один signed I, а для каждой source-функции и каждой новой функции обучаются собственные C. Матрицы имеют вид

$$
\begin{aligned}
W_{t,dh}&=\operatorname{sgn}(I_{dh})C_{t,|I_{dh}|},\
f_t(x)&=\frac{1}{\sqrt H}\sum_{h=1}^{H}
\operatorname{ReLU}\!\left(b+\sum_d x_d W_{t,dh}\right),
\qquad C_{t,0}=0.
\end{aligned}
$$

Первый наблюдаемый инвариант — сумма чётных осевых срезов. Если n_k обозначает полное количество позиций группы k, то

$$
\begin{aligned}
G_t(s)&=\sum_{d=1}^{D}\bigl[f_t(se_d)+f_t(-se_d)\bigr]-2D\sqrt H b\
&=\frac{1}{\sqrt H}\sum_{k=1}^{K}n_k\bigl(s|C_{tk}|-b\bigr)_+.
\end{aligned}
$$

Из изломов этой одномерной кривой оцениваются модули кодов; неизвестные целые multiplicities ограничивают допустимые intercepts. Это требует различимых ненулевых модулей и достаточного разрешения/точности измерений. Порядок кодов не сообщает истинных ролей координат или hidden-neuron соответствия между задачами.

Затем координаты добавляются в случайном зарегистрированном порядке. Для каждого уже восстановленного neuron-prefix проверяются все продолжения0/±K; их неизвестные multiplicities дают линейную модель по наблюдаемым prefix-срезам. Целые количества неотрицательны и сохраняют количество нейронов каждого parent-prefix. Минимизируется ошибка функции по полной Gram-метрике, а не Euclidean расстояние counts. QP, unit/pair moves и conditional-parent solve — известные инструменты. Conditional exactness не означает global integer optimum. Оценка C и ранняя ошибка prefix могут изменить правильный дискретный выбор.

```text
Для каждой source-функции, без teacher-I/C:
    Оценить |C| по сумме чётных осевых срезов:
        integer-intercept DP initialization + numerical curve fit;
        принять checkpoint по отдельным axis-validation наблюдениям.
    Начать с H пустых neuron-prefixes.
    В фиксированном случайном порядке входов:
        Построить ReLU atoms для0/±K продолжений каждого parent.
        По training prefix-срезу найти допустимые counts по task-loss.
        Проверить numerical feasibility/gap; дискретно улучшить counts.
        В refit-абляции уточнить C при жёстком prefix,
            выбирая checkpoint по prefix-validation.
        Продолжить найденные префиксы; при rank failure сохранить отказ.
    Для каждого полного native I дообучить только C на T,
        выбирая checkpoint по fit-validation H.
    Сохранить до4 лучших различных I/вариантов поиска по H.

Общий для всех конкурентов внешний протокол G23:
    Пул кандидатов четырёх source-функций; canonical dedup I.
    Для каждого I сбросить все численные C и optimizer states.
    Независимо обучить C для каждой source-задачи из32signed starts:
        обучение на T, старт/checkpoint по H; I не менять.
    Заморозить все кандидаты и предсказатели до открытия meta-Y.
    Выбрать один I/метод по среднему meta-MSE четырёх задач.
    Заморозить весь выбор до teacher-I audit.
    Отдельно измерить exact mask, unsigned sharing и full signed I;
        bank-contains-true-I отделить от ошибки выбора.

На новой функции:
    Перенести только выбранный I. C обучить заново из32signed starts.
    Выбрать numerical checkpoint на target-validation;
        target test открыть после whole fit freeze.
```

Canonical dedup перебирает названия/знаки групп и перестановки скрытых нейронов, сохраняя имена входных координат. C после такого переименования должен оставаться signed: positive-only fit не проверяет все эквивалентные параметризации нового кодбука. Истинное I доступно только позднему аудиту и отдельному numerical oracle, не сбору банка или выбору.

В завершённом G22 estimated-C метод точен18/18 при умеренном шуме/high precision и12/18 при сильном; true-C диагностический контроль18/18. Усиление дискретного solver само по себе не устранило этот разрыв. G23 завершил первую структурную проверку на6новыхI: общий prefix-I точен6/6 приSD.2 и5/6 приSD2, маска6/6 в обоих случаях; denseGN+DP4/6 и4/6, LC3/6 и3/6. Это результаты данного малого benchmark, не вывод о всех сетях или полном Yeh T/V контроле. Дорогие усреднённые active-query observations, knownb/readout и малое число геометрий остаются ограничениями.

Банк/meta-selection применяется также LC/LUT-Q/joint categorical/denseGN+DP и не является собственным новым extractor. Отдельный зарегистрированный T/V/H Yeh-control ищет shared P сразу по четырём задачам и выдаёт native MAP; его common4 численная оценка/отбор такие же. Он завершён: direct inverse и literalNeumann20 дали по1/6exactI при каждомnoise в даннойадаптации/настройках. Перенос на8новыхC/I завершён: prefixcleanMSE8,62e−7 и0,009857, denseGN+DP0,26186/0,31789. Факторная абляция банка и критерия показала одинаковое число exactI при task0/mean4 scores на фиксированном банке: выигрыш source1→common4 здесь объясняется bank coverage, а не измеренным улучшением общего критерия. Generic finite-alphabet recovery, доверительные области C и ReLU boundary reconstruction известны; приоритет именно prefix-compilation и общее преимущество над сильными конкурентами не установлены.
