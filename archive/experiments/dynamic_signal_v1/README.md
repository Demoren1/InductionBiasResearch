# Dynamic Signal: извлечение структуры из исходных MLP

Рабочий отчёт: [описание постановки и сравнения](../../reports/worknotes/DYNAMIC_SIGNAL_STRUCTURES_2026-11-01.md).

Это адаптация Dynamic Signal Distribution: 16 неизвестных групп по8 входов, один случайно расположенный знаковый сигнал, общая скрытая перестановка входов. На каждой задаче новый сигнал. Плотная MLP128→32ReLU→1 и модели с фиксированным индексатором первого слоя сравниваются по классификации.

## Воспроизведение

Нужны Python, NumPy, SciPy, scikit-learn, PyTorch с CUDA, Matplotlib. Все команды запускать из корня репозитория. Выбор карты — через `CUDA_VISIBLE_DEVICES`.

1. `python -m experiments.dynamic_signal_v1.benchmark` — исходные/калибровочные/разработочные целевые данные с фиксированным seed.
2. `python -m experiments.dynamic_signal_v1.run --stage calibrate --noise-id S --size N` — S=0,1,2; N=256,1024,8192.
3. `python -m experiments.dynamic_signal_v1.source --noise-id S --calibration-size 1024` — начальные банки для всех S. Повторить с8192 для S=0,1; для S=2 выбранная настройка не меняется, результаты переиспользуются.
4. `python -m experiments.dynamic_signal_v1.relations --noise-id S` — второй способ извлечения. Он использует только исходные разреженные веса/readout и известные бюджеты числа групп/ролей/фильтров; истинная перестановка не читается.
5. `python -m experiments.dynamic_signal_v1.prior --noise-id S --name relations --bank-dir experiments/dynamic_signal_v1/runs/v1/banks_relations/noise_S --stage train` — обучение распределения индексаторов.
6. `python -m experiments.dynamic_signal_v1.select_bank` — один исходный банк выбирается по одинаковым отложенным исходным задачам при всех уровнях шума.
7. `python -m experiments.dynamic_signal_v1.confirmation --stage prepare` — подготовка этапа подтверждения. Переносит выбранный исходный генератор без переобучения на все уровни шума. Целевые данные пока не создаются.
8. Для каждой пары S∈{0,1,2}, N∈{128,512,2048,8192} выполнить калибровку `run --stage calibrate`, `prior --stage calibrate --name relations --bank-dir BANK` и `competitors --stage calibrate`. Во всех командах указать `--protocol experiments/dynamic_signal_v1/protocol_confirmation.json --noise-id S --size N`.
9. Для S=0,1,2 и N=2048,8192 выполнить `long_control --stage calibrate` с теми же аргументами протокола. Для всех12 пар S,N выполнить `weight_sharing --stage calibrate`, затем `refine_wsr --noise-id S --size N` — отдельный подбор опубликованного WSR-субградиента и локальное расширение границ штрафов/шага.
10. `python -m experiments.dynamic_signal_v1.confirmation --stage freeze` — проверяет завершение калибровки, сохраняет хеши настроек и только затем генерирует16 новых целевых задач.
11. Повторить команды сравнения из пунктов8–9 с `--stage target` (кроме `refine_wsr`: он только калибровочный). Никакие целевые результаты не используются для изменения настроек.

Все названия модулей выше подразумевают префикс `python -m experiments.dynamic_signal_v1.`. BANK берётся из `runs/v1/bank_selection/selection.json`.

`runs/` содержит регенерируемые большие данные и полные веса, в Git не включается. Компактные метрики, индексаторы, конфигурации и кривые экспортируются отдельно в `results/`; исходные веса, на которых построены индексаторы, сохраняются. Авторегрессивные чекпойнты воспроизводятся обучением; для проверки экспортируются их SHA-256.

## Разработка и независимое подтверждение

`protocol.json`/`runs/v1` — разработочные эксперименты. Их результаты выявили чувствительность к объёму выборки, регуляризации кодбука и выравниванию столбцов. Их нельзя выдавать за нетронутый финальный тест после этих изменений.

`protocol_confirmation.json`/`runs/v2` — отдельное подтверждение: точный подбор под каждый объём данных, расширенные диапазоны параметров,16 новых целевых направлений сигнала. Исходные данные и калибровочные задачи прежние. Выбор по целевой query для остановки/старта предусмотрен протоколом и одинаков у всех; итоговый test для этого не используется.

У задачи одна общая скрытая структура. Этот эксперимент проверяет извлечение и перенос структуры, но не необходимость авторегрессии и не генерацию экспоненциального числа новых сочетаний. Известные бюджеты групп/ролей — дополнительное предположение второго извлекателя, а не результат обучения.

## Результат и графики

Независимый основной результат приσ0,25 и2048 обучающих примерах: AR96,84%, mask-only92,17%, Adam82,60%, SGD83,06%. Разница AR−mask-only4,67п.п., pairedbootstrap95%[4,43;4,91] по16 новым задачам. Частоты/одинIпрактическиравныAR. Приσ0,4,n128структурныйметодпроигрываетпереносувесов; полныйнаборусловийсохранён.

`python -m experiments.dynamic_signal_v1.report` строит таблицы и основные графики; затем `python -m experiments.dynamic_signal_v1.indexator_audit` строит полные цветные индексаторы и рисунок весов с отдельной шкалой. Последний модуль только анализирует готовые результаты: истинные группы применяются для оформления и проверки, без изменения обучения/настроек.

`python -m experiments.dynamic_signal_v1.export_results` экспортирует v1; для v2 добавить `--protocol experiments/dynamic_signal_v1/protocol_confirmation.json`. Графики воспроизводятся также из компактного `results/v2`, если `runs/v2/target_fit` отсутствует. Для шага4 нужны сохранённые исходные веса из `results/v1/banks*` либо их повторное обучение.

После экспорта `python -m experiments.dynamic_signal_v1.compact_evidence` уменьшает архив HPO: в калибровочных NPZ индексаторы хранятся как `indices_unique` (uint8) и `indices_inverse`; восстановление: `indices_unique[indices_inverse].astype("int64")`. Калибровочные кривые усреднены по задачам/стартам отдельно для каждой конфигурации и названы `*_history_by_config.json.gz`. Итоговые метрики каждого запуска сохранены полностью. Целевые индексаторы и полные целевые train/query-кривые не меняются; банк для обучения prior также остаётся в исходном формате. Манифест экспорта пересчитывается после сжатия.

`python -m experiments.dynamic_signal_v1.repeat_banks --replica R`, где R=1,…,5, повторяет основное сравнение при σ=0,25 и n=2048. Каждый повтор создаёт новую перестановку входов, 12 исходных и 16 целевых задач, заново собирает три исходных банка и выбирает один по исходной validation. Затем заново обучает MADE. Seeds всех пяти повторов заданы в `repeat_banks.py` заранее. Работники могут выполняться параллельно на разных свободных GPU через `CUDA_VISIBLE_DEVICES`.

Настройки целевых методов, температура генерации, 8 стартов и бюджеты шагов перенесены из `results/v2` без нового подбора. Сравниваются все 13 методов основной таблицы, включая длинные Adam/SGD. Остальные 11 сочетаний шума и размера выборки в этих повторах не запускаются. Пропускается только старый извлекатель по отдельным столбцам: его результат не используется relational-конвейером.

После завершения всех пяти повторов `python -m experiments.dynamic_signal_v1.repeat_report` проверяет замороженные входы, сохраняет компактные доказательства в `results/bank_repeats/` и строит сравнение, train/query loss, recall и индексаторы в `figures/bank_repeats/`. При агрегировании независимыми единицами считаются пять банков; иерархический bootstrap пересэмплирует сначала банки, затем задачи внутри банка. При пяти банках такой интервал следует читать вместе с результатами каждого повтора.

`python -m experiments.dynamic_signal_v1.repeat_report --from-export` пересоздаёт таблицы и рисунки из компактного архива, без исходных наблюдений и повторного обучения.
