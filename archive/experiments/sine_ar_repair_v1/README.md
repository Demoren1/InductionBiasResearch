[диагностики порога](../../reports/worknotes/SINE_AR_FILTER_DIAGNOSIS_2026-11-03.md).
Замороженные правила: [protocol.json](protocol.json),
[selection_protocol.json](selection_protocol.json).

## Что сравнивается

Все новые priors используют один исходный строгий банк случайных решений:
244 карточки, 192 train / 52 validation, восемь различных масок.
IMP не используется. Учитель, исходный фильтр и разделение пар не меняются.
На целевых функциях все численные параметры инициализируются заново.

- Joint MADE: ширина, learning rate, weight decay и длительность обучения.
- Token noise: случайная замена входных битов по эмпирическим маргиналам.
- Cross-output noise: замена чужого выходного столбца независимой карточкой
  при предсказании своего. Целевые маски остаются исходными.
- Два независимых MADE, по одному на известный выход.
- Архивные Neural Functional + VAE, обычный и partwise, с тремя весами KL.
  Partwise восстанавливает выход при замене чужой половины latent шумом.
- VAE только по маскам и контроль равных весов исходных задач.

Разделение на два выхода известно из архитектуры; координаты учителя
при обучении и выборе не используются. Это явное предположение о допустимой
композиции, а не открытие произвольного разбиения сети на модули.

NF означает **Neural Functional**. Для архивного encoder восстановлены
нормированные source-веса и средний градиент на исходной query-выборке.
`provenance.json` хранит расхождение восстановленной query-ошибки и хеши.
Это сравнение восстановленной архитектуры на текущем банке, а не точное
воспроизведение прежнего положительного запуска.

## Выбор настроек и оценка

26 конфигураций, три seed, checkpoints 100/300/1000/3000/6000.
AR temperature делит logits; VAE scale умножает стандартный нормальный
latent. Для шумных AR сравниваются обучение с шумом и добавление шума
также при генерации. Source-validation служит диагностикой, выбор делается
по конечной query MSE решателя на отдельных функциях.

Screen: функции 13021/13022, по два поиска на seed.
Confirmation: функции 13023/13024, по восемь поисков на seed.
Знакомые и calibration-only пары получают одинаковый вес.
Два лучших screen-кандидата каждой семьи перепроверяются на confirmation.
Затем на тех же confirmation-функциях настраиваются SGD и отбор структур.
Это адаптивная калибровка; её оптимистичность проверяется на новых функциях.

После записи `selection_frozen.json` создаются target-функции 14031/14032.
На каждый метод приходится 384 поиска новых сочетаний и 384 знакомых.
Для каждой выбранной семьи сохраняются два режима: исходные 32+32 fit
и откалиброванные численное обучение/распределение попыток.

В каждом поиске неизменно 65 536 обновлений отдельных моделей, batch 64:
4 194 304 обучающих примера. Изменение числа шагов компенсируется числом
попыток. Половина бюджета идёт на предложения, половина — на свежие refit.
Топ-4 означает четыре **различные** маски, выбранные по лучшему query MSE
первой стадии; refit распределяется между ними по кругу. Во второй стадии
также нет доступа к истинной маске или population MSE. Dense SGD/Adam
имеют 64 независимых старта по 1024 шага и отдельную калибровку lr/scale.

Success означает аналитическую population MSE < 0.1. Глобальная
оптимальность не доказана. Доверительные интервалы в анализе — bootstrap
по координатным парам, условно на одном source-банке; для новых сочетаний
есть лишь четыре независимые пары. 384 поиска нельзя считать 384
независимыми задачами. Обучение и калибровка priors — дополнительные
вычисления сверх равного целевого бюджета.

## Запуск

Из корня репозитория, Python с PyTorch/CUDA, NumPy и Matplotlib:

```bash
python -m experiments.sine_ar_repair_v1.run --phase initialize
python -m experiments.sine_ar_repair_v1.run --phase train
python -m experiments.sine_ar_repair_v1.run --phase screen
python -m experiments.sine_ar_repair_v1.calibrate --phase candidates
python -m experiments.sine_ar_repair_v1.calibrate --phase families
python -m experiments.sine_ar_repair_v1.calibrate --phase controls
python -m experiments.sine_ar_repair_v1.calibrate --phase freeze
python -m experiments.sine_ar_repair_v1.calibrate --phase evaluate
python -m experiments.sine_ar_repair_v1.analyze --phase aggregate
python -m experiments.sine_ar_repair_v1.analyze --phase diagnose
python -m experiments.sine_ar_repair_v1.analyze --phase figures
python -m experiments.sine_ar_repair_v1.package_results
```

Для независимых конфигураций/семей/методов доступны `--shard N --shards M`
и `--device cuda:0`; GPU можно выбирать через `CUDA_VISIBLE_DEVICES`.
Фаза с зависимостями начинается после завершения всех shard предыдущей.
Запуск сохраняет результаты в заданной `output` папке и не перезаписывает
существующий запуск. Для повторения нужен новый путь в копии протокола.
Исходные результаты других экспериментов не изменяются.

`analyze --phase diagnose` выполняется только после замораживания настроек:
генерирует 3 × 32 768 масок на prior, измеряет покрытие, новую композицию
частей и эмпирическую зависимость выходов. Эти измерения не используются
для выбора гиперпараметров. Сохраняются гистограммы всех 65 536 масок.

## Сохраняемые артефакты

Git содержит протоколы и снимок исходников, банк с восстановленными
признаками, кривые всех обучений, все calibration-оценки и сырые целевые
поиски, а также checkpoints трёх seed выбранного prior каждой семьи.
Остальные checkpoints остаются локально и исключены из Git: их можно
повторно получить фазой обучения. Диагностика VAE по всем checkpoints
сохранена в `latent_diagnostics.json`; её скрипт — `latent_diagnostics.py`.
Старые результаты не заменяются новыми таблицами.
Траектории всех кандидатов опубликованы в `*_history.npz` с исходной
точностью float32; объёмные JSON-копии остаются локально. Манифест хранит
хеши обоих представлений. Основной AR для вывода выбирается по
confirmation-query среди пяти AR-вариантов, согласно заранее сохранённому
`report_protocol.json`, и не переопределяется по целевому результату.
