# Градиент и кривизна при поиске индексатора

Продолжение диагностики `sharing_diagnostics_v1`: проверяем, достаточно ли близости к свободным весам Z для нахождения переносимого шэринга. Все варианты ищут общий целочисленный индексатор с нулём и тремя кодами с привязанными отрицаниями. Маска и группы свободно меняются, численные кодбуки отдельные для каждой функции.

## Постановка

Скрытая свёртка W14×16 с неизвестными перестановками входов и выходов. Gaussian входы и коэффициенты, шум 0.1, у каждой source-функции 4 support + 4 query. Независимые задачи для выбора checkpoint содержат 4 support + 64 query. Поиск не получает истинную маску, число подключений или группировки. K=3 и размеры известны.

Первый pilot с восемью функциями оказался почти неразличающим: все методы и learning rate имели одинаковые минимальные validation loss. Он сохранён в `results/20261105/gradient_and_adaptation`. До открытия подтверждающих геометрий зарегистрирован окончательный pilot с четырьмя функциями в `results/20261105/gradient_and_adaptation_lowdata`. Это не отбор по тестовым результатам. Финальная проверка использует 2/4/8/64 вложенных source-подмножеств; настройки всех бюджетов выбираются только на четырёх функциях.

## Варианты

- `z_euclidean`: совместный индексатор всех source-функций, отдельные Z/C, исходная евклидова проекция.
- `z_hessian`: те же старт, L-step и dual schedule. Проекция учитывает полную эмпирическую кривизну, но опускает линейный член градиента.
- `z_taylor`: к предыдущей проекции добавлен градиент в точке Z+U. Для линейной MSE это минимизация фактической source-ошибки плюс близость к Z+U. Временный кодбук этой проекции обучается на всех source-наблюдениях; при оценке и переносе кодбуки сбрасываются и обучаются только на support.
- `meta_stop`: старт с выбранного `z_euclidean`; кодбук точно адаптируется на support, общий жёсткий индексатор меняется по query-градиенту с остановленной производной обучения кодбука.
- `meta_full`: тот же алгоритм, но с дифференцированием через support-fit кодбука. Forward жёсткий; backward через дискретизацию является surrogate STE. Непрерывное состояние — коэффициенты общего базиса A, а не исходные скалярные веса Z: это отдельный вариант адаптации структуры.
- `projected_stop/full`: после наблюдаемого на pilot разрастания маски у STE Adam зарегистрирован дополнительный контроль. Сырой градиент нормируется по максимальному модулю, одновременно предлагаются шесть глобальных жёстких проекций; source-query line search выбирает улучшение после нового support-fit C. До 80 шагов, без дополнительного HPO. Через позиции с новым fit C для каждого значения алгоритм не перебирает.
- `query_edits`: прежняя однопозиционная дискретная поправка как контроль, максимум 64 улучшения. Внутри градиентных алгоритмов такого перебора нет.

Для полного гессиана назначения связаны между собой. Проектор использует локальные проходы по входным координатам и точный условный fit C; глобальное решение проекции не заявляется. Это не старый scalar DP. Вариант `z_hessian` специально меняет только критерий проекции при неизменном обновлении Z; это диагностическая абляция, без новой гарантии ADMM.

На окончательном pilot выбранный евклидов старт уже имел validation на уровне шума. Поэтому до мета-подбора зарегистрирована калибровка `meta_calibration.json`: на pilot слепо меняются четыре разных позиции найденного I, одинаково у обоих STE, обоих projected-вариантов и дискретного контроля. Это позволяет исследовать исправление структуры. В подтверждающих запусках старт не портится. Дополнительные projected-варианты зарегистрированы в `gradient_controls.json` до открытия подтверждающих геометрий.

## Защита от смешения причин

Штраф разреженности отключён во всех Z-вариантах. Их сетки одинаковы: три конечных rho × два dual step; четыре старта, 80 раундов. Метаградиентные варианты имеют по шесть learning rate и по четыре малых возмущения одного исходного индексатора; 800 шагов, фиксированный ridge 1e-6 для дифференцируемого inner-fit. Checkpoint и итоговая оценка используют одинаковый точный МНК без ridge. Сначала выбираются настройки проекций, затем мета-адаптации. Все состояния новых шести геометрий замораживаются до открытия teacher и создания 100 новых коэффициентных задач.

При изотропных входах population-квадрат изменения предсказаний совпадает с нормой Фробениуса изменения весов. Поэтому проверяем эмпирическую метрику и переобучение кодбуков, не предполагая заранее, что гессиан обязательно лучше.

Диагностика использует один общий пул кандидатов из checkpoints и случайных локальных возмущений, без teacher. Сравнивает евклидову близость с проекционным C и с support-fit C, диагональную/полную кривизну, полный Taylor и фактическую query-ошибку. Равенство полного Taylor реальной линейной MSE — математическая тождественность, а не самостоятельный эмпирический успех.

## Запуск

Через `python -m experiments.sharing_gradient_v1.run --root RESULTS --stage STAGE`. Порядок: `register`, четыре GPU-shard `pilot_projection`, `freeze_projection`, четыре shard `pilot_meta`, `freeze`, четыре shard `confirmation`, `models_freeze`, четыре shard `evaluate`. Для shard используются `--shard 0..3 --shards 4`, GPU задаётся через `CUDA_VISIBLE_DEVICES`. Отдельно запускаются `diagnostics` и `report` из этого пакета.

Новые software tests не создаются и не запускаются. Выполняются только сами исследования, проверка направленной производной inner-fit, точного Taylor, lint и просмотр графиков. Используются все четыре свободные V100 0–3; занятые чужими процессами 4–7 не затрагиваются. Результат относится к линейной скрытой свёртке, не к nonlinear DeepSets/Pattern/синусам.
