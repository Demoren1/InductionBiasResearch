# Новые функции с известной маской

> Архив эксперимента 20 октября. Старые команды и формат W/G+AGOP описаны для истории; актуальный W/G-код и команды — в [overlapping_groups](../../overlapping_groups/README.md). Разовые скрипты удалены.

Протокол от 20 октября 2026 реализует уточнённую постановку: функции
различаются, но правильная бинарная структура первого слоя совпадает
со структурой функций, использованных при обучении VAE. Декодеры W/G
4213, 4214, 4215 заморожены; VAE и исходный IMP-банк не переобучаются.

Используются все 24 обучающих семейства. Функции 0–3 относятся к прежнему
обучению VAE; новые функции 4/5 служат адаптации маски, новые функции 6/7 —
проверке её переноса. Внутри семейства заново выбираются входные веса
учителя, пороги и выходные коэффициенты. Правильная маска остаётся той же.
Наблюдения генерируются независимо; support/query/test: 2048/2048/8192.
Функции 8–11 остаются резервом для будущей итоговой оценки.

Генератор знает учителя для получения мягких меток. Поиск получает только
support/query функций 4/5, одинаковые исходные параметры MLP, замороженный
декодер и общий банк кандидатов. Эталонная маска и идентификатор целевого
семейства не участвуют в выборе кандидата. До доступа к функциям 6/7
результат фиксируется в `selection.pt` с контрольной суммой в
`selection_seal.json`. Аналитические сравнения и обучение oracle выполняются
после этой фиксации.

Для Gumbel и evolution: восемь стартов, 40 шагов, 1608 candidate-fit,
по две адаптационные функции и одной инициализации. Fitness: 64 шага SGD,
lr 0,2, восемь шагов leaky-ReLU warmup, L2=1e-5, средняя query BCE.
Настройки сохранены от предыдущего переноса; меняется разделение функций,
а не настройка оптимизации под новые результаты. Случайный поиск оценивает
1608 z, включая те же восемь начальных. Большие пулы оцениваются одним
батчем 1608 кандидатов.

Дополнительный контроль — прямой выбор из 1608 обучающих IMP-масок:
по 67 на каждое из 24 семейств, только карты с `network_roles == train`.
Этот пул одинаков для всех целевых функций и декодеров и не фильтруется
по аналитическому качеству. Точная маска учителя не добавляется в пул.
Выбор использует ту же короткую fitness и бюджет 1608.

На функциях 6/7 для каждой фиксированной маски обучаются новые MLP:
три парные инициализации, 2000 шагов Adam, lr 0,03, выбор checkpoint
по query раз в 100 шагов, 200 шагов leaky-ReLU warmup. Обычная плотная
MLP 48→8→1 — один экземпляр в каждом повторе, без ансамбля. Oracle имеет
правильную маску. IMP выполняется непосредственно на каждой функции 6/7,
начинает с того же dense checkpoint и возвращается к исходной инициализации
после обрезания. Это обычный IMP-контроль на новой функции; прежний отчёт
использовал другой контроль — перенос IMP с адаптационных функций.

IMP вычисляется один раз на семейство и переиспользуется между seed
декодера; dense и oracle также имеют одинаковые исходные seeds. Эти повторы
не считаются независимыми. Итоговая единица усреднения и погрешности —
семейство: 24 независимые структуры; функции и seed усредняются внутри него.
Все обучения выполняются на CUDA; CPU используется для файлов и статистики.

Запуск из корня репозитория:

```bash
python3 -u tmp/overlapping_groups_20261020/launch_known_mask.py
```

По умолчанию используются все восемь GPU с ограничением 12 GiB на процесс
(10 GiB аллокатору PyTorch и 2 GiB резерва). Код сохраняет параметры,
исходники, контрольные суммы декодера/банка, историю поиска, итоговые веса,
маски, метрики, время и пиковую память. После завершения всех 72 заданий
автоматически создаёт сводку и графики в `runs/known_mask_v1`.

Проверка завершена: [результаты](KNOWN_MASK_RESULTS_2026-10-20.md).
В ходе запуска по указанию пользователя задействован `boost_known_mask.py`:
вся оставшаяся очередь запущена одновременно, до пяти заданий на GPU.
Он меняет только диспетчеризацию; данные, seeds, бюджет и исходники
исследовательских заданий сохранены. Загрузка всех восьми GPU достигла 99%.

После подбора fitness выполнен полный повтор с Adam lr=0,1, 64 шагами
и warmup 32: [результат и команда](TUNED_FITNESS_RESULTS_2026-10-20.md).
Сохранённая переносимая конфигурация — `known_mask_tuned_config.json`.
У диспетчера теперь есть `--workers-per-device` (по умолчанию 4)
и `--cache-from` для повторного использования тех же наблюдений и IMP.
Исходная конфигурация `known_mask_config.json` сохранена для истории.
